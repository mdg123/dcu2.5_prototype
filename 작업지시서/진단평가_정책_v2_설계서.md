## 1. 변경 요약 (Before → After)

| 항목 | v1 (현재) | **v2 (변경 후)** |
|------|-----------|------------------|
| 진단 단위 | 1 노드(단원/차시) = 2문항 고정 | **1 노드(단원) = 그 단원의 차시 수만큼(최대 5개) 1문항씩** |
| 통과 기준 | 2/2 정답 (100%) | **정답률 ≥ 60%** |
| 큐 정렬 | 큐에 들어온 순서(BFS bottom-up) | **우선순위 큐: 목표 학년·학기에 가까운 단원 먼저** |
| drill-down | 백엔드 별도 EP, 수동 호출 | **실패 시 자동 안내 + 3옵션(다시/더 내려가기/바로 학습) — 사용자 선택** |
| 종료 조건 | 연속 2회 통과 OR 최대 3단계 OR 큐 소진 | **큐 소진 OR 사용자가 "바로 학습" 선택** (단계 상한 제거) |
| 사전 고지 | 없음 | **시작 모달에서 선수 단원 N개·순서·변동 가능성 안내** |
| 결과 저장 | 노드별 통과 여부만 | **노드별 진단지 구성, 응답, 정답률, 종료 사유까지 보존** |
| 직속 선수 2개 이상 | 큐 순서 사실상 임의 | **각 단원 진단지를 별도로 풀고, 진단 완료 후에야 다음 단원 진행** |

## 2. 핵심 알고리즘

### 2.1 우선순위 큐 — 학년·학기 거리 기반

- **절대학기(`gradeAbs`)** 산출식:
  - 초등: `grade*2 + (semester-1)` → 예: 1-1=2, 6-2=13
    (정확히 0-base 정렬이 필요하면 `(grade-1)*2 + (semester-1)`로 통일해도 무방. **내부 비교만 필요**하므로 식은 일관성만 유지)
  - 중학: `14 + (grade-1)*2 + (semester-1)` → 7-1=14, 9-2=19
  - 고등: `20 + (grade-1)*2 + (semester-1)` → 10-1=20, 12-2=25
  - 위 식은 **단조 증가**가 보장되면 됨. `school_level`이 `elem/mid/high`로 들어오므로 분기.
- **거리(`distance`)** = `|gradeAbs(target) − gradeAbs(candidate)|`
- **우선순위**: distance **오름차순** (가까울수록 먼저)
- **동률 처리 (tie-break)**:
  1. `subject` 알파벳 순(또는 한국어 정렬: 국어→수학→영어→과학→사회→…)
  2. `sort_order` 오름차순(같은 학기 내 교과서 순)
  3. `node_id` 사전순 (재현성 보장)

```javascript
// 의사코드 — db/self-learn-extended.js 신규 헬퍼
function _gradeAbs(schoolLevel, grade, semester) {
  const g = Number(grade) || 0;
  const s = Number(semester) || 1;
  if (schoolLevel === 'mid')  return 14 + (g - 1) * 2 + (s - 1);
  if (schoolLevel === 'high') return 20 + (g - 1) * 2 + (s - 1);
  return g * 2 + (s - 1); // elem (기본)
}

function _nodeDistance(targetAbs, candidateNode) {
  return Math.abs(targetAbs - _gradeAbs(
    candidateNode.school_level, candidateNode.grade, candidateNode.semester
  ));
}

function _sortQueueByPriority(queueIds, targetAbs) {
  const rows = _fetchNodeMeta(queueIds); // {node_id, subject, grade, semester, school_level, sort_order}
  return rows.sort((a, b) => {
    const d = _nodeDistance(targetAbs, a) - _nodeDistance(targetAbs, b);
    if (d !== 0) return d;
    if (a.subject !== b.subject) return a.subject.localeCompare(b.subject, 'ko');
    if (a.sort_order !== b.sort_order) return a.sort_order - b.sort_order;
    return a.node_id.localeCompare(b.node_id);
  }).map(r => r.node_id);
}
```

### 2.2 큐 운용 흐름

```
초기화:
  queue = sortByPriority( 직속 선수 노드 모두, targetAbs )
  current = null
  진행: ── while queue.length > 0 ──
    current = queue.shift()                  // 우선순위 1순위
    진단지 = buildDiagnosisSheet(current)    // 최대 5문항
    학생이 진단지 풀이
    rate = correct / total
    if rate >= 0.60: PASS → 해당 단원 선수 진단 불필요
    else FAIL → 3옵션 모달
       ┌ "다시 진단": 같은 노드를 큐 맨 앞에 push (새 문항으로)
       ├ "더 내려가기": current의 직속 선수 N개를 큐에 add → 재정렬
       └ "바로 학습": 진단 종료, current 단원에서 학습 시작
완료:
  queue 소진 → 학습 출발점(가장 깊이 통과한 노드의 바로 위) 안내
```

### 2.3 직속 선수 2개 이상 시 (사용자 예시 — A·B·C·D)

```
edges: D(2-2) → B(3-2) → A(4-1)
       C(3-1)         → A(4-1)
targetNode = A(4-1)  → targetAbs = 8 (예: 4*2+0)

[Step 1] A 진단 시작 (선수 노드 큐 만들기)
  직속 선수: [B(3-2), C(3-1)]
  distance: B→|8-7|=1, C→|8-6|=2
  sorted queue: [B, C]
  사전 고지 모달:
    "이 단원을 잘 풀기 위해 2개 단원을 먼저 진단합니다.
     1) B 단원(3학년 2학기)
     2) C 단원(3학년 1학기)
     ※ 결과에 따라 진단할 단원이 늘어나거나 순서가 바뀔 수 있어요."

[Step 2] current=B → 진단지 풀이 → 80% PASS
  B의 선수(D) 진단 불필요. queue=[C]

[Step 3] current=C → 진단지 풀이 → 50% FAIL
  3옵션 모달: 사용자가 "더 내려가기" 선택
  C의 직속 선수: [없음/혹은 더 하위]  ← 예시 그대로면 없음
  사용자 예시 흐름: B가 FAIL이었다면 D 추가 → C(3-1) vs D(2-2) 재정렬
  distance: C→2, D→|8-5|=3 → queue=[C, D]
```

## 3. 진단지 구성 규칙

### 3.1 단원(node_level=2) → 차시(node_level=3) 조회

```sql
SELECT node_id, lesson_name, sort_order
FROM learning_map_nodes
WHERE parent_node_id = :unitNodeId
  AND node_level = 3
ORDER BY sort_order ASC;
```

### 3.2 진단지 조립 규칙

| 차시 수 | 진단지 구성 |
|---------|-------------|
| 0개 (차시 없음·해당 노드 자체가 차시) | 해당 노드 자체에서 **1~2문항** 추출 (fallback: 기존 `_pickQuestionForNode` 재사용) |
| 1~5개 | **모든 차시**에서 각 1문항 (총 1~5문항) |
| 6개 이상 | **sort_order 역순(최신 차시 우선) 5개 차시** 선별, 각 1문항 (총 5문항) |

> **이유**: "역순"은 단원 후반부일수록 단원의 핵심 도달 목표에 가까운 차시이기 때문. 단원 도입부 차시만 풀고 통과하는 빈틈 방지.

### 3.3 문항 선택

- 차시 노드에서 `_pickQuestionForNode(lessonId, 'medium')` 재사용 (난이도 medium 고정 — v1 정책 유지)
- 차시에 문항이 없으면 그 차시는 **skip** (진단지 총 문항 수 줄어듦)
- 진단지 총 문항이 0이 되면 → 해당 단원 **자동 통과** 처리(문항이 없으므로 진단 불가 → 차상위로 진행) + 결과에 "진단 불가(문항 없음)" 표기

```javascript
function _buildDiagnosisSheet(unitNodeId) {
  const lessons = db.prepare(`
    SELECT node_id, lesson_name, sort_order
    FROM learning_map_nodes
    WHERE parent_node_id = ? AND node_level = 3
    ORDER BY sort_order ASC
  `).all(unitNodeId);

  let picked;
  if (lessons.length === 0) {
    // 차시가 없으면 단원 자체에서
    const q = _pickQuestionForNode(unitNodeId, 'medium');
    return q ? [{ lessonId: unitNodeId, question: q }] : [];
  }
  if (lessons.length <= 5) {
    picked = lessons;
  } else {
    // 역순 5개
    picked = [...lessons].reverse().slice(0, 5);
  }
  const sheet = [];
  for (const l of picked) {
    const q = _pickQuestionForNode(l.node_id, 'medium');
    if (q) sheet.push({ lessonId: l.node_id, lessonName: l.lesson_name, question: q });
  }
  return sheet; // 길이 0~5
}
```

## 4. 통과 판정

- **정답률** = `correct / total`
- **통과**: `정답률 ≥ 0.60`
- **불통과**: `정답률 < 0.60`
- 정답률은 `user_node_status.correct_rate`에 0~1 범위로 저장(기존 컬럼 재사용)
- 통과 시 `diagnosis_result = 'mastered'` (정답률 ≥ 0.80) 또는 `'proficient'` (0.60 이상)
- 실패 시 `diagnosis_result = 'developing'` (0.40~0.60) 또는 `'needs_review'` (< 0.40)

> 사용자 정책에 명시된 **"통과 시 그 위로 학습 시작 가능"** 은 큐 종료 시 학습 출발점 결정 로직에 반영(§7).

## 7. 종료 조건 & 학습 출발점 결정

### 7.1 종료 사유 (endReason)

| 사유 코드 | 발생 시점 | UI 메시지 |
|-----------|-----------|-----------|
| `queue_empty` | 큐가 비어 자연 종료 | "진단을 모두 마쳤어요." |
| `user_decided_to_learn` | 실패 모달에서 "바로 학습" 선택 | "{단원}부터 학습을 시작할게요." |
| `no_questions_anywhere` | 큐 내 모든 단원에 문항 없음 | "진단할 문항이 부족합니다. 학습맵에서 직접 선택해 주세요." |

> **단계 상한(max_steps=3) 제거**. `currentDepth`는 UI에 "지금까지 진단한 단원 수: 3개"처럼 **진행 표시용**으로만 사용.

### 7.2 학습 출발점 결정

- 큐 소진 종료 시: `history` 중 **가장 마지막에 통과한 노드의 바로 위(원래 진단 큐의 부모 방향)** 를 출발점으로 추천.
- 통과 노드가 없으면: 가장 깊이 실패한 노드부터 학습하도록 안내(현 v1과 동일).
- 사용자가 "바로 학습" 선택 시: 그 단원을 출발점으로.

## 8. DB 스키마 변경

기존 `diagnosis_sessions` 컬럼은 그대로 두고 **JSON 필드(queue_nodes, per_node_answers, difficulty_path)에 v2 정보 추가** 저장.

### 8.1 `diagnosis_sessions` 컬럼 의미 재정의

| 컬럼 | v1 의미 | v2 의미 |
|------|---------|---------|
| `queue_nodes` (TEXT/JSON) | 단순 string[] | `[ "nodeIdA", "nodeIdB", ... ]` — **우선순위 정렬된 순서** |
| `current_node_id` | 현재 진단 노드 | 동일 |
| `current_difficulty` | medium 고정 | 동일 (사용 안 함) |
| `difficulty_path` (TEXT/JSON) | 노드 단계 경로 | **노드별 결과 누적** — `[{ node, passed, correct, total, rate, sheetMeta, endedAt }, ...]` |
| `per_node_answers` (TEXT/JSON) | 노드별 응답 | 동일 — `{ nodeId: [{questionId, lessonId, correct, userAnswer}, ...] }` |

### 8.2 신규 (선택) 컬럼

> **권장: 컬럼 추가 없이 기존 JSON 필드만 확장**. 마이그레이션 부담 회피.
> 다만 분석/통계 편의를 위해 다음을 검토:

```sql
-- (선택) 추후 추가 검토
ALTER TABLE diagnosis_sessions ADD COLUMN target_grade_abs INTEGER;  -- 우선순위 계산 캐시
ALTER TABLE diagnosis_sessions ADD COLUMN end_reason VARCHAR(40);    -- queue_empty / user_decided_to_learn / no_questions_anywhere
ALTER TABLE diagnosis_sessions ADD COLUMN sheet_size_max INTEGER DEFAULT 5;
```

### 8.3 진단 이력 저장 (사용자 강조 — "저장되어야 함")

기존 `diagnosis_answers` 테이블에 **모든 응답이 row 단위로 저장**되므로 별도 변경 불필요. 단:

1. `diagnosis_answers.node_id`는 **차시 노드(lessonId)** 가 들어가도록 변경(v1은 단원 노드가 들어감). 분석 시 차시 단위 정답률 산출 가능.
2. `difficulty_path` JSON에 진단지 메타(`sheetMeta = { totalLessons, pickedLessons, reversed }`) 보존하여 추후 "어떤 차시들을 진단했는지" 복원 가능.

### 8.4 결과 노출 (학생 이력 화면)

기존 `listDiagnosisHistory(userId)` 활용 + 응답에 다음 필드 추가:
```jsonc
{
  "sessionId": ...,
  "targetNode": { ... },
  "perNode": [
    { "nodeId": "...B", "title": "...", "passed": true, "correctRate": 0.8, "sheetSize": 5 },
    { "nodeId": "...C", "title": "...", "passed": false, "correctRate": 0.5, "sheetSize": 4 }
```

|--------|------|------|-----------|
| POST | `/api/self-learn/diagnosis/start` | **수정** | 응답에 `prereqCount`, `queueOrder`, `sheet` 추가. `currentDifficulty` 의미 약화. |
| POST | `/api/self-learn/diagnosis/:id/answer` | **수정** | 단일 문항 응답이 아닌 **진단지(sheet) 단위 일괄 응답**으로 변경 가능. 또는 1문항씩 유지하되 sheet 진행률(`sheetIndex`, `sheetTotal`)을 응답에 포함. |
| POST | `/api/self-learn/diagnosis/:id/submit-sheet` | **신규(권장)** | 한 노드의 진단지 전체(answers 배열)를 한 번에 제출 → 정답률 계산 + 통과 판정 + 다음 액션(자동 진행/3옵션) 반환 |
| POST | `/api/self-learn/diagnosis/:id/retry-node` | **신규** | 현재 노드를 재진단(per_node_answers 초기화 + 새 진단지) |
| POST | `/api/self-learn/diagnosis/:id/drill-down` | **수정** | 직속 선수 추가 후 `_sortQueueByPriority` 재정렬 |
| POST | `/api/self-learn/diagnosis/:id/finish` | **수정** | `endReason`을 body로 받음 (`user_decided_to_learn` 등) |
| GET  | `/api/self-learn/diagnosis/:id/state` | **수정** | 큐를 우선순위 정렬된 형태로 hydration, 현재 sheetIndex/sheetTotal 포함 |

### 9.1 `submit-sheet` 응답 예시

```jsonc
{
  "success": true,
  "nodeFinished": true,
  "nodePassed": false,
  "correctRate": 0.4,
  "results": [
    { "lessonId": "...", "questionId": 12, "isCorrect": true },
    { "lessonId": "...", "questionId": 17, "isCorrect": false },
    ...
  ],
  "nextAction": {
    "type": "choose",            // "auto_next" | "choose" | "complete"
    "options": [
      { "id": "retry",      "label": "다시 진단하기" },
      { "id": "drill_down", "label": "더 아래 단원 진단하기", "prereqCount": 1 },
      { "id": "learn_here", "label": "바로 학습하기" }
    ]
  },
  "queueRemainingHydrated": [ /* 다음 단원 미리보기 */ ]
}
```

`nextAction.type === 'auto_next'` 이면 통과 → 다음 단원 진단지 자동 표시.
`'complete'` 이면 종료 → 결과 화면.

### 10.1 영향 받는 파일

### 10.2 화면 흐름

```
[학습맵 단원 클릭]
   ↓
[사전 고지 모달] ─── (취소)
   ↓ (진단 시작)
[진단지 풀이 화면]
   - 상단: 현재 단원 N/총M
   - 좌측: 진단 큐 시각화 (현재/대기/완료)
   - 중앙: 문항 1~5 순차 표시 또는 1페이지 5문항
   ↓ (5문항 모두 응답)
[단원 결과 미니 카드]
   ├ 통과 → 0.8초 후 자동으로 다음 단원
   └ 실패 → [3옵션 모달]
                ├ 다시 진단 → 진단지 풀이 화면(새 문항)
                ├ 더 내려가기 → [큐 추가 안내 토스트] → 다음 단원 진단
                └ 바로 학습 → [학습 출발점 결과 화면] → drawer
   ↓
(큐 소진)
   ↓
[최종 결과 화면]
   - 진단한 단원 목록(통과/실패/정답률)
   - 학습 출발점 추천 + "바로 학습 시작" 버튼
   - 학습목록 자동 추가 안내
```

### 10.3 진단 큐 시각화 (사이드 패널)

```
┌──── 진단 진행 ────┐
│ ✓ B 단원  3-2  80% │   ← 완료(통과)
│ ▶ C 단원  3-1  …   │   ← 현재
│ ○ D 단원  2-2  대기│   ← 대기 (실패로 추가됨)
└────────────────────┘
```

색상: 통과 = `#10B981`, 현재 = `#2563EB`, 실패 = `#EF4444`, 대기 = `#94A3B8`.

### 10.4 공통 UI 스케일 준수

- 사전 고지/실패 모달 제목 19~20px, 본문 16px, 버튼 16px
- 큐 시각화 항목 14~15px, 단원명 16px
- 모달 최대 너비 640~720px (좌·우 padding 28px)

```

[1] 학생, 학습맵에서 A(4-1) 단원 클릭 → "진단 받기" 클릭
[2] 사전 고지 모달:
     - "이 단원을 잘 풀기 위해 2개 단원을 먼저 진단합니다.
        1순위 B 단원(3학년 2학기)
        2순위 C 단원(3학년 1학기)
        ※ 결과에 따라 진단 단원이 늘어나거나 순서가 바뀔 수 있어요."
     [진단 시작] 클릭
[3] B 단원 진단지 (B의 차시 8개 → 역순 5개 차시에서 각 1문항 = 5문항)
     학생: 4/5 정답 (80%) → 통과
     자동 토스트: "B 단원 통과! 다음 단원으로 넘어갑니다."
[4] C 단원 진단지 (C의 차시 4개 → 모두 = 4문항)
     학생: 2/4 정답 (50%) → 실패

     사용자: "더 아래 단원 진단하기" 선택
[5] C의 직속 선수 진단 추가 → 큐에 [C의 선수1] 추가 → 우선순위 재정렬
     (만약 B가 FAIL이었다면 D 추가 → C/D 거리 비교 → C 우선)
[6] 추가된 선수 단원 진단지 풀이 → ...
[7] 큐 소진 → 최종 결과 화면
     - 통과: B

     - 학습 출발점: 가장 깊이 실패한 단원부터 안내
     - "추천 단원 N개를 학습목록에 추가했습니다." 토스트
```

## 12. 잔존 위험 / 결정 사항

| # | 이슈 | 결정 |
|---|------|------|
| 1 | 우선순위 동률(거리 같음) 처리 | subject(ko sort) → sort_order → node_id 순 tie-break (§2.1) |
| 2 | 차시가 0개인 단원 | 단원 노드 자체에서 1~2문항 추출 (§3.2 폴백) |
| 3 | 진단지에 들어갈 문항이 부족(차시는 있지만 문항이 없음) | 가용 문항만으로 진단지 구성. 문항 0개면 자동 통과 + "진단 불가" 표기 |
| 4 | 학년 다른 교과 선수 단원 혼재 | distance 동률이면 subject 우선순위로 분리. 동일 학년 동일 학기 내 다교과는 sort_order로. |
| 5 | "다시 진단" 무한 반복 | 같은 노드 retry는 **세션당 최대 2회**로 제한(소프트). 3회 시도 시 "더 내려가기" 권장 안내 토스트. |
| 6 | drill-down 후 새로 들어온 노드도 통과 못 하면 또 더 내려가기 가능? | 가능. 큐 깊이 상한 없음. 단 UI에 "현재 진단 깊이: N단계" 표시. |
| 7 | 진단 이력 저장 — 차시 단위 분석 | `diagnosis_answers.node_id`에 lessonId 저장으로 변경. 분석은 lesson→unit 매핑으로 가능. |
| 8 | xAPI 호환 | 기존 `finishDiagnosis`의 xAPI spool은 그대로 유지. `assessment_type='D'`, score=총정답/총문항. |
| 9 | 교사·관리자 진단 시작 (`teacher_no_record`) | v1과 동일하게 데모 응답만 — 변경 없음. |
| 10 | 모바일(< 768px) 진단지 5문항 표시 | 1문항씩 페이지네이션(좌우 스와이프 또는 다음 버튼). 큐 시각화는 상단 가로 스크롤 칩으로 축소. |
| 11 | "통과 시 그 위로 학습" 동선 | 큐 소진 결과 화면의 "바로 학습 시작" 버튼이 **목표 노드 A**의 drawer를 직접 엶. |
| 12 | 단계 상한 제거 → 사용자 피로 우려 | UI에 "총 진단 단원 수"·"누적 풀이 시간"을 실시간 표시. 매 단원 종료 후 "그만하기" 보조 버튼 제공. |
