## 0. 1쪽 요약 (Executive Summary)

### 핵심 원칙

1. **클래스에서 만든 수업/과제/평가는 기본 "비공개"**다. 학생은 즉시 그 클래스에서 볼 수 있지만, 다른 사용자(다른 교사·다른 클래스)에게는 **공개되지 않는다**.
2. 클래스에서 만들면 **자동으로 채움콘텐츠 > 나의 보관함에 한 행이 생긴다**(원본과 연결된 그림자 콘텐츠).
3. 다른 사용자에게 **공개하고 싶으면 사용자가 직접 채움콘텐츠 > 나의 보관함에서 "공개"로 토글**한다. 이때 **관리자 승인 흐름**(`pending → approved`)을 탄다.
4. **승인은 "다른 사용자에게 공개할 때만" 필요하다**. 본인이 자기 클래스에 가져다 쓰는 행위, 또는 이미 공개된 콘텐츠를 보관함에 담은 뒤 본인 수업에 가져다 쓰는 행위는 **승인 불필요**.
5. 채움콘텐츠 **나의 보관함에는 두 종류**가 섞여 있다:
   - 내가 직접 만든 것(클래스에서 자동 등록 + 채움콘텐츠에서 직접 만들기) — 공개 여부와 무관하게 본인이 쓸 수 있음.
   - 다른 사용자가 만든 공개 콘텐츠를 내가 담은 것 — 공개됐기에 어차피 사용 가능.

### "가시성 두 차원" 모델

| 차원 | 의미 | 컬럼 | 값 |
|------|------|------|----|
| **클래스 내부 가시성** | 같은 클래스 학생에게 보이는가 | `status` (객체별 의미 유지) | `draft`(초안, 학생 안 보임) / `published`(학생 노출) |
| **마켓플레이스 공개** | 다른 사용자에게 공개되는가 | `is_public` (신규) + `marketplace_status` (신규, content 미러) | `is_public 0/1` + `marketplace_status: none / pending / approved / rejected` |

두 차원은 **독립**. "학생에 공개"가 "마켓플레이스 공개"를 의미하지 않으며 그 반대도 아니다.

## 1. 정책 상세

### 1.1 객체별 기본값

| 객체 | 클래스 내부 가시성(`status`) 기본값 | 마켓플레이스 공개(`is_public`) 기본값 | 보관함 자동 등록 |
|------|------|------|------|
| 수업(lessons) | `draft` (개설자 선택으로 `published`) | **0 (비공개)** | **예 — content_type='bundle'로 등록** |
| 과제(homework) | `published` (현행 유지) | **0 (비공개)** | **예 — content_type='assignment'로 등록** |
| 평가(exams) | `direct: active`, `waiting: waiting`, `draft: draft` (현행 유지) | **0 (비공개)** | **예 — content_type='exam'으로 등록** |
| 채움콘텐츠 직접 만들기(contents) | — | 사용자가 모달에서 선택 (기본 0, 옵션으로 1) | (자기 자신) |

### 1.2 마켓플레이스 공개 흐름

```
[1] 클래스에서 만들기
    ↓
   원본(lessons/homework/exams) + 그림자(contents, is_public=0, marketplace_status='none')
   동시 INSERT (트랜잭션)
    ↓
[2] 본인 클래스에서 학생에게 노출
    - 별도 승인 불요
    - lessons.status='published' 로 토글 시 학생에게 보임
    - homework/exams는 생성 시 이미 노출
    ↓
[3] (선택) 다른 사용자에게 공개하고 싶을 때
    채움콘텐츠 > 나의 보관함 → 해당 항목 → "공개로 전환" 토글
    ↓
   contents.is_public = 1, contents.status = 'pending' (admin은 즉시 'approved')
    ↓
[4] 관리자 승인/반려
    ↓
   approved: 공개 콘텐츠 목록에 노출, 다른 사용자가 검색·보관 가능
   rejected: is_public 유지하되 'rejected', 공개 목록 제외
```

### 1.3 다른 사용자가 가져다 쓰는 흐름

```
다른 사용자 A가 본인 보관함에 담음 (content_collections INSERT)
    ↓
A가 자기 클래스에서 "공개콘텐츠/보관함에서 가져오기"로 수업·평가에 사용
    ↓
승인 불요. 이미 공개·승인된 콘텐츠이므로 즉시 사용 가능
    ↓
A의 수업·평가는 다시 [1]로 회귀 — A의 새 수업·평가는 A의 비공개 항목으로 생성
```

### 1.4 "본인이 자기 클래스에 다시 쓰기" 흐름

```
교사 본인이 만든 비공개 수업·평가·과제도 본인 보관함에 그림자로 존재
    ↓
다른 클래스에서 "내 보관함에서 가져오기"로 동일 콘텐츠 재사용 가능
    ↓
승인 불요 — 본인 콘텐츠이므로 is_public·status와 무관하게 사용
```

## 2. 상태 모델

### 2.1 lessons.status (의미 재정의 없이 유지)

| 값 | 의미 (현행 그대로) |
|----|----|
| `draft` | 초안 — **같은 클래스 학생에게도 안 보임** |
| `published` | 학생 노출 — **같은 클래스 학생만 봄** (마켓플레이스 공개와 무관) |
| `scheduled` | 예약 — 시작일까지 학생 안 보임 |
| `archived` | 보관 |
| `pending` / `rejected` | (기존) 큐레이션 큐 — 본 정책에서는 사용 안 함, 호환 유지 |

### 2.2 homework.status (의미 유지)

| 값 | 의미 |
|----|----|
| `draft` | 초안 |
| `published` | 학생 노출 (기본값) |
| `closed` | 마감 |
| `archived` | 보관 |

### 2.3 exams.status (의미 유지)

| 값 | 의미 |
|----|----|
| `draft` | 임시저장 |
| `waiting` | 대기 모드 — 교사가 시작 클릭 전까지 학생 응시 차단 |
| `active` | 응시 가능 |
| `closed` | 마감 |

### 2.4 contents.is_public + contents.status (현행 유지 + 의미 명확화)

| `is_public` | `status` | 의미 |
|----|----|----|
| 0 | `draft` | 사용자만 보임 (본인 보관함 전용, 마켓플레이스 비노출) |
| 1 | `pending` | 공개 신청 — 관리자 승인 대기 |
| 1 | `review` | 검토 중 |
| 1 | `hold` | 보류 |
| 1 | `approved` | 공개 — 마켓플레이스 노출 |
| 1 | `rejected` | 반려 — 마켓플레이스 비노출 (사용자 본인은 여전히 보관함에서 봄) |

### 2.5 신규: contents.linked_source

원본(lessons/homework/exams) ↔ 그림자(contents) 연결을 위한 컬럼.

| 컬럼 | 타입 | 의미 |
|------|------|------|
| `linked_source_type` | TEXT | `lesson` / `homework` / `exam` / NULL(독립 콘텐츠) |
| `linked_source_id` | TEXT | 원본 PK (lessons.id, homework.id, exams.id — TEXT 통일) |
| `linked_class_id` | INTEGER | 원본이 속한 클래스 id (열람 권한 + 자동 동기화 추적용) |

**역방향 인덱스** (`UNIQUE(linked_source_type, linked_source_id)`) — 원본 한 건당 그림자 한 건.

## 3. DB 스키마 변경 계획 (idempotent ALTER)

`db/schema.js`에 다음 마이그레이션 블록을 **순서대로** 추가한다. 모두 PRAGMA 검사로 이미 존재하는 컬럼은 건너뛴다.

### 3.1 contents: 마켓플레이스 연결 컬럼 추가

```js
// 콘텐츠 ↔ 원본(수업/과제/평가) 연결 컬럼
{
  const cols = db.prepare("PRAGMA table_info(contents)").all().map(c => c.name);
  if (!cols.includes('linked_source_type')) {
    db.exec("ALTER TABLE contents ADD COLUMN linked_source_type TEXT");
    console.log('[DB] contents.linked_source_type 컬럼 추가');
  }
  if (!cols.includes('linked_source_id')) {
    db.exec("ALTER TABLE contents ADD COLUMN linked_source_id TEXT");
    console.log('[DB] contents.linked_source_id 컬럼 추가');
  }
  if (!cols.includes('linked_class_id')) {
    db.exec("ALTER TABLE contents ADD COLUMN linked_class_id INTEGER");
    console.log('[DB] contents.linked_class_id 컬럼 추가');
  }
  db.exec("CREATE UNIQUE INDEX IF NOT EXISTS idx_contents_linked ON contents(linked_source_type, linked_source_id) WHERE linked_source_type IS NOT NULL");
}
```

### 3.2 lessons: 마켓플레이스 공개 차원 분리

`status`의 의미는 **클래스 내부 가시성**으로 유지. 마켓플레이스 공개는 그림자 콘텐츠의 `is_public/status`로 일원화 → **lessons 본체에는 컬럼 추가 안 함** (단일 진실 원천 = contents 행).

> **설계 이유**: lessons에 `is_public` 추가 시 두 곳(원본 + 그림자)을 동기화해야 하고, 공개 흐름은 `채움콘텐츠 > 나의 보관함`에서 일어나므로 그림자 한 곳에서 처리하는 편이 단순.

### 3.3 homework, exams: 동일 원칙

본체에 `is_public` 추가하지 않음. 그림자 contents 행에서 공개 상태 관리.

### 3.4 exams.source_content_id 의미 보강

기존 `source_content_id`(이미 존재)는 "공개 콘텐츠에서 가져온 평가"를 표시. 본 정책에서는 그림자 contents 행의 `linked_source_id`로 역방향 추적도 가능해진다. 양방향 호환.

### 3.5 마이그레이션 후 기존 데이터 처리

신규 객체는 자동 동기화로 그림자 콘텐츠가 생성된다. **기존 lessons/homework/exams는 일회성 백필 스크립트로 그림자 행 INSERT**.

```js
// 한 번만 실행되는 백필 (마이그레이션 직후)
const backfillMarker = db.prepare("SELECT value FROM kv_store WHERE key = ?").get('content_shadow_backfill_done');
if (!backfillMarker) {
  db.transaction(() => {
    // 1) lessons 백필
    const lessons = db.prepare("SELECT id, title, description, teacher_id, class_id, created_at FROM lessons").all();
    for (const l of lessons) {
      const exists = db.prepare("SELECT id FROM contents WHERE linked_source_type = 'lesson' AND linked_source_id = ?").get(String(l.id));
      if (!exists) {
        db.prepare(`INSERT INTO contents (creator_id, title, description, content_type, is_public, status, linked_source_type, linked_source_id, linked_class_id, created_at)
          VALUES (?, ?, ?, 'bundle', 0, 'draft', 'lesson', ?, ?, ?)`)
          .run(l.teacher_id, l.title, l.description || null, String(l.id), l.class_id, l.created_at);
      }
    }
    // 2) homework, 3) exams 동일 패턴
    db.prepare("INSERT OR REPLACE INTO kv_store (key, value) VALUES (?, ?)").run('content_shadow_backfill_done', '1');
  })();
}
```

> **주의**: `kv_store` 테이블이 없다면 `system_settings` 등 기존 테이블 활용. 또는 `PRAGMA user_version`을 활용.

## 4. 자동 동기화 로직

### 4.1 INSERT 동기화 (원본 생성 시)

`db/lesson.js`, `db/homework.js`, `db/exam.js`의 `create*` 함수를 **트랜잭션으로 감싸** 그림자 contents 행 동시 INSERT.

```js
// db/lesson.js — createLesson 내부
function createLesson(classId, teacherId, data) {
  return db.transaction(() => {
    const info = db.prepare(`INSERT INTO lessons (...)`).run(...);
    const lessonId = info.lastInsertRowid;

    // 그림자 콘텐츠 자동 등록
    db.prepare(`INSERT INTO contents
      (creator_id, title, description, content_type, is_public, status, linked_source_type, linked_source_id, linked_class_id, subject, grade, achievement_code, school_level)
      VALUES (?, ?, ?, 'bundle', 0, 'draft', 'lesson', ?, ?, ?, ?, ?, ?)`)
      .run(teacherId, data.title, data.description || null, String(lessonId), classId,
           data.subject_code || null, data.grade_group || null, data.achievement_code || null, data.school_level || null);

    return getLessonById(lessonId);
  })();
}
```

같은 패턴을 `createHomework`(content_type='assignment'), `createExam`(content_type='exam')에도 적용.

### 4.2 UPDATE 동기화

원본 제목·설명·교과·성취기준 등 메타 변경 시 그림자 contents 동기화. **트랜잭션 + try/catch** — 동기화 실패 시 로그만 남기고 원본 변경은 commit.

```js
function updateLesson(id, data) {
  return db.transaction(() => {
    // ... 기존 UPDATE 로직
    try {
      const fieldsToSync = {};
      if (data.title !== undefined) fieldsToSync.title = data.title;
      if (data.description !== undefined) fieldsToSync.description = data.description;
      // is_public/status는 마켓플레이스 흐름에서만 변경 — 여기선 건드리지 않음
      if (Object.keys(fieldsToSync).length > 0) {
        const sets = Object.keys(fieldsToSync).map(k => `${k} = ?`).join(', ');
        const vals = Object.values(fieldsToSync);
        db.prepare(`UPDATE contents SET ${sets} WHERE linked_source_type = 'lesson' AND linked_source_id = ?`)
          .run(...vals, String(id));
      }
    } catch (e) { console.error('[SYNC] lesson→content', e); }
    return getLessonById(id);
  })();
}
```

### 4.3 DELETE 동기화

원본 삭제 시 그림자 콘텐츠도 삭제 (cascading). 단, **그림자가 다른 사용자에게 공개·승인된 상태(is_public=1, status='approved')**이면 보존 여부를 정책으로 결정:

**권장**: 원본 삭제 시 그림자는 `linked_source_id = NULL`로 끊고 "원본 삭제됨" 표시. 이미 공개된 콘텐츠를 다른 사용자가 보관·사용 중일 수 있으므로 **물리 삭제 금지**.

```js
function deleteLesson(id) {
  db.transaction(() => {
    db.prepare("UPDATE contents SET linked_source_id = NULL, linked_source_type = 'lesson_deleted' WHERE linked_source_type = 'lesson' AND linked_source_id = ?")
      .run(String(id));
    db.prepare("DELETE FROM lessons WHERE id = ?").run(id);
  })();
}
```

비공개(`is_public=0`) 그림자는 함께 물리 삭제해도 안전:

```js
db.prepare("DELETE FROM contents WHERE linked_source_type = 'lesson' AND linked_source_id = ? AND is_public = 0").run(String(id));
```

### 5.1 API 변경

`PUT /api/contents/:id` 의 기존 `is_public` 전환 로직은 **그대로 유지**한다 (`routes/content.js:598-612`).

```js
// 0 → 1 전환: status = 'pending' (admin은 'approved')
// 1 → 0 전환: status = 'draft'
```

**추가 검증**: 그림자 콘텐츠(`linked_source_type IS NOT NULL`)도 동일 흐름. 단, `linked_source_type === 'lesson_deleted'`는 공개 전환 차단(원본 삭제됨).

### 6.2 과제 등록 모달

과제는 현행대로 즉시 published. 추가 안내:

```html
<div class="info-banner" style="background:#EFF6FF;padding:10px 12px;border-radius:8px;font-size:13px;color:#1E40AF;margin-bottom:16px;">
  <i class="fa-solid fa-circle-info"></i>
  만든 과제는 자동으로 <strong>채움콘텐츠 &gt; 나의 보관함</strong>에도 비공개로 담겨요.
  다른 선생님에게 공유하려면 보관함에서 "공개"로 전환해 주세요.
</div>
```

### 6.3 평가 등록 모달

평가의 `start_mode`(direct/waiting) 라벨은 현행 유지. 동일한 안내 배너 추가.

### 6.4 채움콘텐츠 > 바로 만들기 (현행 유지)

`is_public` 선택 옵션을 명확히 노출 (현재도 존재). 라벨 통일:

```html
<label class="checkbox-row">
  <input type="checkbox" id="contentIsPublic" />
  <span>지금 바로 다른 사용자에게 공개 신청 (관리자 승인 후 공개)</span>
</label>
```

## 9. 테스트 시나리오 (E2E)

### 9.1 클래스 → 보관함 자동 등록 + 학생 즉시 노출

1. teacher1 로그인 → 클래스 A 진입
2. 수업 만들기: 제목 "5월 22일 수학", status `published`
3. **검증**:
   - 클래스 A 수업 탭에 노출 ✓
   - student1로 로그인 → 클래스 A 수업 탭에 노출 ✓
   - teacher1 로그인 → 채움콘텐츠 > 나의 보관함에 "5월 22일 수학" (배지: "수업꾸러미(자동)", 비공개) ✓
   - 공개 콘텐츠 탭에서 검색 시 미노출 ✓
   - student2(다른 클래스)로 로그인 → 채움콘텐츠에서 검색 미노출 ✓

### 9.2 보관함에서 공개 전환 → 승인 → 노출

1. teacher1 → 채움콘텐츠 > 나의 보관함 → "5월 22일 수학" → 공개 토글 클릭
2. **검증**: 배지 "공개 승인 대기" ✓, 공개 콘텐츠 탭 미노출 ✓
3. admin 로그인 → 승인 관리 → 해당 항목 승인
4. **검증**:
   - teacher2 로그인 → 공개 콘텐츠 검색 시 노출 ✓
   - teacher2 → 본인 보관함에 담기 ✓
   - teacher2 → 본인 클래스 B 수업에 "내 보관함에서 가져오기"로 추가 ✓ (승인 불요)

### 9.3 본인이 비공개 콘텐츠 재사용

1. teacher1 → 클래스 A에서 수업 생성 (비공개)
2. teacher1 → 클래스 C 진입 → 수업 만들기 → "내 보관함에서 가져오기" → 비공개 수업도 목록에 표시 ✓
3. 가져오기 후 클래스 C에 수업 등록 ✓ (승인 불요)

### 9.4 원본 삭제 → 그림자 처리

1. teacher1 → 클래스 A의 비공개 수업 삭제 → 보관함에서도 삭제 ✓
2. 별도: 이미 공개·승인된 수업을 원본 삭제 → 보관함 항목은 보존되되 "원본 수업 삭제됨" 표시, 공개 전환 차단 ✓

### 9.5 권한 회귀

- student1이 `PUT /api/contents/:id`로 다른 사용자 콘텐츠 공개 전환 시도 → 403 ✓
- 비owner 교사가 owner 의 클래스 수업 수정 시도 → 403 ✓

## 10. 회귀 위험 요소 및 대책

| 위험 | 영향 | 완화책 |
|------|------|------|
| 자동 동기화 트랜잭션 실패 시 원본만 INSERT됨 | 그림자 결손, 보관함에서 안 보임 | `db.transaction()` 으로 한 번에 commit, 실패 시 throw |
| 백필 스크립트 중복 실행 | 그림자 중복 행 | `kv_store` 또는 `system_settings`에 완료 플래그 + `UNIQUE INDEX idx_contents_linked` |
| 기존 `searchContentsForLesson` 가 비공개 콘텐츠 노출 | 다른 사용자에게 비공개 콘텐츠 노출 위험 | 쿼리에 `(c.creator_id = ? OR (c.is_public = 1 AND c.status = 'approved'))` 조건 보장 (현재 코드 점검 필요) |
| `contents.status` CHECK 제약 — `'draft'` 가 빠진 경우 | INSERT 실패 | schema.js 라인 392 확인 결과 `'draft'` 포함 ✓ |
| 공개 콘텐츠 삭제 시 보관함에 담은 다른 사용자 영향 | 깨진 참조 | `ON DELETE` 없이 soft-delete 또는 안내 후 cascade |
| 원본 lesson 수정 시 그림자 메타와 불일치 | 검색·표시 혼란 | UPDATE 동기화 로직(4.2)로 보강. is_public/status는 동기화 대상 제외 (마켓플레이스 흐름 독립) |
| 평가지의 questions·answers 변경 | 그림자 콘텐츠는 questions를 별도 보관하지 않음 — 공개 시 import-from-content 로직이 원본을 읽어 복사 | export-to-content 트리거 시 시점 스냅샷 또는 동기화 로직 추가 |
| 기존 `exportToContent`(cbt-extended.js:52)가 별도로 contents 행 생성 | 중복 그림자 가능 | 자동 동기화 도입 후 `exportToContent`는 deprecated 또는 "공개 전환" 메서드로 대체 |
| `is_public=1` 인 채로 만들어진 기존 contents가 status='approved'로 자동 통과 | 기존 콘텐츠 누락된 승인 절차 회피 | 신규 정책은 신규 INSERT에만 적용. 기존 콘텐츠는 그대로 |

## 11. 구현 순서 권고 (Backend → Frontend 순)

1. **Phase 1 — 스키마 마이그레이션** (db/schema.js)
   - contents에 `linked_source_type`, `linked_source_id`, `linked_class_id` 컬럼 + 인덱스
2. **Phase 2 — 자동 동기화 로직** (db/lesson.js, db/homework.js, db/exam.js)
   - create/update/delete 트랜잭션 래핑
   - 백필 스크립트 실행
3. **Phase 3 — 보관함 검색·표시 보강** (db/content.js, routes/content.js)
   - `getMyContents`, `searchContentsForLesson`에 linked_source 표시 컬럼 포함
   - 권한 체크 강화 (비공개는 본인만)
4. **Phase 4 — UI 라벨 변경** (public/class/class-home.html, public/content/index.html)
   - 수업·과제·평가 모달 안내 배너
   - 보관함 배지 + 공개 토글 툴팁
5. **Phase 5 — 관리자 화면** (public/admin/content-approval.html)
   - 그림자 항목 식별 표시 + 원본 링크
6. **Phase 6 — E2E 테스트** (전 시나리오)

## 12. 미결 항목 (사용자 의사결정 필요)

1. **이미 공개·승인된 콘텐츠를 다시 비공개로 되돌릴 때** — 현재 코드는 `status='draft'`로 되돌림. 정책으로 명시: "비공개로 되돌리면 즉시 공개 목록에서 사라지고, 다른 사용자 보관함에 이미 담긴 것은 어떻게 할지?" → **권장**: 다른 사용자 보관함 항목은 유지하되 "원본이 비공개로 전환됨" 표시.
2. **그림자 콘텐츠 사용자 직접 삭제 허용 여부** — 보관함에서 자동 등록된 비공개 그림자를 사용자가 삭제하면 원본 수업·과제·평가는 어떻게 처리? → **권장**: "원본을 먼저 삭제해 주세요" 안내 (그림자만 단독 삭제 불가).
3. **content_type 명명** — `bundle` / `assignment` / `exam` 중 과제는 기존 콘텐츠 타입에 `assignment`가 없음. 신규 타입 추가 또는 `bundle`로 통일?
   - **권장 신규**: `lesson_bundle`, `assignment`, `exam_paper`로 명확히 구분.
4. **백필 시점** — 기존 데이터 양이 적으면 즉시, 많으면 별도 마이그레이션 명령으로 분리.

**문서 끝**. 본 설계는 사용자가 명시한 정책을 코드 변경 최소 + 단일 진실 원천(contents 그림자 행) 원칙으로 풀이한 결과이며, 감리·PM 합의 후 Backend 서브에이전트에게 구현 지시를 발행하는 입력으로 사용된다.
