# 성장기록 > 포트폴리오 신규 기능 기획서

**문서명**: 종합 포트폴리오 PDF 보고서 (One-File Portfolio Report)
**작성**: UI 디자이너 서브에이전트
**대상 페이지**: `public/growth/portfolio.html`
**연관 라우트**: `routes/growth.js`, `db/growth-extended.js`, `db/growth.js`
**RFP 근거**: SFR-033 (포트폴리오), SFR-034 (성장보고서)

---

## 1. 목적·배경

### 1-1. 사용자 핵심 요구
> "학생이 자신의 특정 과제를 선택해서 **1개의 포트폴리오 PDF 파일로 종합하여 다운**받아볼 수 있는게 있으면 좋겠어. 표지도 있고, 과제도 보고, 역량이나 기타 여러가지 볼거리가 있어서 **하나의 보고서 형태**의 포트폴리오가 만들어지면 좋겠어."

### 1-2. 현재 한계 (실측 확인)
- `public/growth/portfolio.html` line 540 — `quick-btn` "PDF 내보내기"는 `alert('준비 중입니다.')` 더미만 존재
- line 622-657 — 보고서 생성 모달이 있지만 클릭 시 토스트만 띄우고 실제 PDF 다운로드 없음
- `package.json` — PDF 생성 패키지(puppeteer/jsPDF/html2canvas) 의존성 **0**
- 학생용 "공유하기" 버튼(line 548)도 토스트만 출력, 실제 공유 링크 발급 없음

### 1-3. 출시 가치
- (학생) 학기/학년 마무리에 **자기소개서·진학 자료**로 활용 가능한 한 권의 포트폴리오를 직접 만들어 보유
- (학부모) 자녀의 성장을 한 PDF로 받아보는 명료한 산출물 → 학교 신뢰도 상승
- (교사) 학기말 평가·진로상담 시 학생별 PDF를 빠르게 확보 (관찰 코멘트 자동 포함)
- (RFP SFR-033) "포트폴리오 인쇄·공유 기능" 정식 충족

## 2. 사용자 시나리오 (학생 기본 8단계)

```
[1] 진입       성장기록 메뉴 > 포트폴리오 페이지 진입
              (현재 위치: 좌측 사이드바 "포트폴리오" 라벨 활성)
                    ↓
[2] 시작       우상단 또는 우측 빠른실행 카드의
              "📑 종합 PDF 다운로드" 버튼 클릭
                    ↓
[3] 옵션 설정   PDF 만들기 모달 — 1단계 "기본 정보를 정해볼까요?"
              · 기간 (필수): [시작일] ~ [종료일] datepicker
                  · 디폴트 = 학년 시작일(현재 학년 3/2) ~ 오늘
                  · 빠른 선택 칩: "이번 학기" / "이번 학년" / "최근 3개월" / "전체"
              · 학교급 (필수): [초등] [중등] [고등] 토글
                  · 디폴트 = 학생 현재 학교급(users.grade_level 기반)
                  · K-12 누적 데이터를 가진 학생은 다른 학교급 전환 가능 (예: 중1 학생이 초등 시절 포트폴리오 PDF 생성)
                  · 선택한 학교급에 해당 데이터 0건이면 inline 경고 + 다음 비활성
              · 표지 사진 선택 (아바타/업로드)
              · 역량 차트 포함 토글 (기본 ON)
              · 활동 타임라인 포함 토글 (기본 ON)
              · 보호자/교사 한 마디 포함 (기본 OFF)
                    ↓
[4] 과제 선택   2단계 "어떤 활동을 담을까요?"
              · 1단계의 기간·학교급 필터로 1차 좁힌 후보 목록만 노출
              · 빠른 선택: 전체 / 인생과제만 / 직접 선택 (체크박스)
              · 후보 0건일 시 "이 기간/학교급에 활동이 없어요" + 1단계 복귀 버튼
                    ↓
[5] 한 마디    3단계 "마지막 페이지에 한 마디 남기기"
              · 본인 소감 (200자 이내, 선택)
              · 인사말 톤 가이드 ("이번 학기를 마치며…" 예시)
                    ↓
[6] 미리보기   4단계 "이렇게 만들어집니다" — A4 미리보기 모달 (90vw × 90vh)
              · 좌측 페이지 썸네일 (1~9페이지)
              · 우측 큰 미리보기
              · 페이지 클릭으로 이동
              · "수정" 버튼으로 1~3단계 복귀
                    ↓
[7] 다운로드   "📥 PDF 다운로드" 버튼 →
              생성 진행 모달 (약 3~8초, 프로그레스 바)
              완료 후 자동 다운로드 + 토스트 "포트폴리오 PDF가 만들어졌습니다"
                    ↓
[8] 사후 액션  완료 모달:
              ① "다시 만들기" (1단계 재진입)
              ② "선생님께 공유" (공유 모달 연동)
              ③ "닫기"
              생성 이력은 좌측 "내 포트폴리오 보고서" 리스트에 자동 등록 (재다운로드/삭제 가능)
```

### 2-1. 교사 시나리오
- 학생 포트폴리오 화면 진입(기존 `teacherPortfolioView`) → 학생 카드 클릭 → 학생 화면 진입 → "이 학생 포트폴리오 PDF" 버튼
- 단, **학생이 1회 이상 본인 PDF를 만든 적 있어야** 활성 (학생의 동의 = "공유 허용" 토글 ON 상태)
- admin 계정은 학생 동의 무관 다운로드 가능 (감사 로그 남김)

### 2-2. 사용자 중심 5원칙 적용
| 원칙 | 적용 |
|---|---|
| (a) 진입 경로 | 1) 우상단 고정 CTA "📑 종합 PDF 다운로드", 2) 우측 빠른실행 카드, 3) 빈 상태 안내 — **3중 진입점** |
| (b) 현재 위치 피드백 | 모달 4단계 진행 표시기 (1 ─ 2 ─ 3 ─ 4), 각 단계 라벨, "현재 X단계 / 4단계" 텍스트 동시 표기 |
| (c) 복귀 동선 | 모든 단계에 "← 이전" 버튼, 우상단 ✕ 닫기, ESC 키 지원, 미리보기에서 "수정" 버튼으로 단계 직접 점프 |
| (d) 빈 상태/오류 | 포트폴리오 0개일 때 PDF 버튼 비활성 + 안내 문구, PDF 생성 실패 시 재시도 버튼 + 에러 상세 |
| (e) 평이한 한국어 | "표지를 만들어볼까요?", "어떤 활동을 담을까요?", "이렇게 만들어집니다" — 초등학생 친화 |

## 3. PDF 보고서 구성 (총 9페이지 표준)

| # | 페이지 | 핵심 내용 | 데이터 출처 |
|---|---|---|---|
| 1 | **표지** | 학생 이름·아바타·학교/학년·기간·다채움 로고·생성일 | `users` + 학생 입력 |
| 2 | **목차** | 자동 생성, 페이지 번호, 클릭(웹뷰)/기재(인쇄) | 본 PDF 자체 |
| 3 | **요약** | 본인 한 마디 + 통계 카드 4개(과제 수·활동 일수·인생과제·성찰 수) | `/portfolio/stats` |
| 4 | **6대 핵심역량 레이더** | 자기관리·지식정보처리·창의적사고·심미적감성·협력적소통·공동체 (현 portfolio.html SVG 기반) | `/api/growth/portfolios/:studentId/report-data` (신규) |
| 5 | **6대 성장영역 막대** | 정서발달·기초학력·학습역량·오늘의학습·독서활동·진로탐색 점수 | `/api/growth/report/student/:studentId` (기존) |
| 6~8 | **선택한 과제별 페이지** | 과제마다 1페이지(또는 1/2페이지). 제목·날짜·과목·교사 코멘트·산출물·본인 회고·역량 태그 | `/api/growth/portfolio/items/:id` |
| 9-1 | **활동 타임라인** | 한 페이지 그래픽 (월별 점·과목 색·삶의 과제 별표) | `/api/growth/portfolio/items` 전체 |
| 9-2 | **마무리** | 학생 한 마디 + (옵션) 보호자 한 마디 + (옵션) 교사 평가 + 서명란 | 학생 입력 + `/report/parent` + `/report/observations` |

### 3-1. 페이지 수 가변 규칙
- **최소** 7페이지: 표지·목차·요약·역량·과제 1·타임라인·마무리
- **권장** 9페이지: 위 + 과제 2개 추가
- **최대** 25페이지: 과제 최대 18개 (한 페이지 1과제 기준)
- 학생이 과제 19개 이상 선택 시 "한 페이지에 2개 묶어 담기" 옵션 제안

### 3-2. 표지 정보 상세
- 학생: 이름(28pt) / 학교·학년·반(14pt) / 학번(12pt 회색)
- 기간: "2026학년도 1학기" 또는 "2026.03.02 ~ 2026.07.20"
- **메타 헤더 (표지 하단 1줄, 13pt 회색 #475569 굵게)**:
  `기간: 2026-03-01 ~ 2026-04-30 / 학교급: 초등`
  · 1단계에서 선택한 필터 값 그대로 노출 (학생/교사가 한눈에 어떤 범위로 만들어진 보고서인지 확인)
  · 학교급 라벨: 초등 / 중등 / 고등 (영문 X, 한국어 통일)
- 사진: 아바타 자동 (이니셜 + 다채움 그라디언트) **또는** 학생이 업로드한 PNG/JPG (1024×1024 이내)
- 다채움 로고: 좌하단 32px, "다채움 — 충북교육청 통합 교육 플랫폼" 11pt
- 생성일: 우하단 11pt 회색 "YYYY.MM.DD 발행"

### 3-3. 과제 페이지 상세 구성 (1/2/3 패턴)
**패턴 A — 풍부형 (한 페이지 1과제)**
```
헤더(과목 색): "수학 | 5학년 1학기"          page n/total
제목 (24pt 굵게)
메타 (12pt 회색): 활동일 · 교사명 · 점수 · 결과
─────────────────────────────────
본인 산출물 (이미지 1장 또는 텍스트 박스)
─────────────────────────────────
교사 코멘트 (인용 박스, 좌측 4px primary 라인)
─────────────────────────────────
나의 회고 (학생 직접 입력, 박스)
─────────────────────────────────
역량 태그 (작은 칩 4~6개)
```

**패턴 B — 콤팩트형 (한 페이지 2과제, 학생 선택 가능)**
- 좌/우 분할, 위 내용 압축 + 회고는 2줄 클램프

### 6-2. PDF 생성 방식 비교 및 권고

| 항목 | (A) 서버 puppeteer (권장) | (B) 클라이언트 jsPDF + html2canvas |
|---|---|---|
| 한글 처리 | Chromium 내장 + Pretendard CDN, 완벽 | jsPDF 한글 지원 까다로움, 폰트 base64 임베드 필요 (~1.5MB) |
| 이미지 처리 | 서버에서 fetch → 안정 | CORS·base64 변환 필요 |
| PDF 품질 | 인쇄 수준 (300dpi) | 캡처 기반 (96~150dpi), 화질 낮음 |
| 텍스트 검색·복사 | 가능 | html2canvas는 이미지화 → **검색 불가** |
| 학교 보안망 | 외부 트래픽 없음 (내부 처리) | 폰트 CDN 외부 호출 필요 |
| 서버 부하 | 페이지당 ~150MB Chromium 인스턴스, 동시 5명까지 | 서버 부하 0 |
| 생성 시간 | 3~6초 | 6~12초 (큰 이미지 캡처 느림) |
| 의존성 추가 | `puppeteer` (~280MB) 또는 `puppeteer-core` + 시스템 Chrome | `jspdf` (~250KB) + `html2canvas` (~50KB) |
| 배포 복잡도 | 중 (서버 Chrome 필요) | 낮음 (클라 단일 파일) |
| 유지보수 | 단일 HTML 템플릿으로 통제 | 브라우저별 캡처 차이 |

#### 권고: **(A) 서버 puppeteer 채택**
**근거**:
1. **한글 깨짐 절대 금지** — RFP는 충북교육청 운영, 한글 보고서 품질이 최우선. 텍스트 검색 가능한 PDF가 정식 기록물 가치 보장.
2. **인쇄 품질** — 학부모/학교 인쇄·제출 시 화질 저하 없음.
3. **학교 보안망 호환** — 클라이언트 외부 폰트 CDN 호출이 차단되는 환경에서도 안정 동작.
4. **단일 템플릿 유지보수** — `views/portfolio-report.ejs`(또는 별도 HTML 템플릿) 한 곳만 관리.

**리스크 완화**:
- 동시 생성 큐(`p-queue`, max concurrency 3) 도입
- 생성 후 `data/reports/{userId}/{reportId}.pdf` 저장 → 24시간 캐시
- 5초 내 응답 SLA, 초과 시 비동기 + 푸시(socket) 알림 패턴

**대안**: 운영 단계에서 서버 부하 한계가 명확해질 경우 **(B) 클라 fallback** 옵션 — 단, 출력 품질 경고 토스트 표시.

## 7. 데이터 모델 / API 설계

### 7-1. 신규 API
#### `GET /api/growth/portfolios/:studentId/report-data?from=YYYY-MM-DD&to=YYYY-MM-DD&schoolLevel=elementary|middle|high`
보고서 1회 조립용 종합 페이로드. 권한: 본인 OR 교사(클래스 멤버) OR admin.

**Query Parameters (모두 필수)**
| 이름 | 타입 | 형식 | 설명 |
|---|---|---|---|
| `from` | string | `YYYY-MM-DD` | 기간 시작일 (포함). 예: `2026-03-01` |
| `to` | string | `YYYY-MM-DD` | 기간 종료일 (포함). 예: `2026-04-30` |
| `schoolLevel` | enum | `elementary` \| `middle` \| `high` | 학교급. 한국어 매핑: 초등/중등/고등 |

1. `users.grade_level` 검증 — 요청 schoolLevel과 학생의 누적 데이터 보유 학교급 교차 검사

3. `competencies`, `growthAreas`, `timeline` 모두 동일 기간/학교급으로 산출

### 7-2. DB 보강

#### (a) 현황 점검 — 학교급 컬럼 부재 확인 (실측)
| 테이블 | 학교급 관련 컬럼 | 비고 |
|---|---|---|
| `users` | ❌ 없음 (`grade INTEGER`만 존재, `db/schema.js` line 14) | **`grade_level` / `school_level` 없음** ← 신규 필요 |
| `portfolio_items` | ❌ 없음 (`grade_year VARCHAR(20)`만 존재, line 733) | 신규 필요 |
| `learning_map_nodes` | ✅ `grade_level VARCHAR(10)` ('초'/'중'/'고') 존재 (line 598) | 참조 모델로 활용 |
| `curriculum_standards`, `subjects` | ✅ `school_level TEXT CHECK IN ('초','중','고','공통')` 존재 | 참조 모델로 활용 |

> 학생 검수 보고서에 언급된 "users.grade_level = 초/중/고"는 현재 스키마에 **존재하지 않음**. PDF 신규 기능 도입과 함께 학교급 컬럼을 신설한다.

#### (b) `users` 컬럼 신규
```sql
-- 학생 현재 학교급 (PDF 위저드 1단계 디폴트로 사용)
ALTER TABLE users ADD COLUMN school_level TEXT;
-- 값 도메인: 'elementary' | 'middle' | 'high' (API 일관)
-- DB 표기: 한국어가 아닌 영문 enum 사용 (i18n·정렬·검색 친화)
-- 마이그레이션: grade 컬럼 기준 자동 채우기
--   1~6  → 'elementary'
--   7~9  → 'middle'
--   10~12 → 'high'
UPDATE users SET school_level = CASE
  WHEN grade BETWEEN 1 AND 6   THEN 'elementary'
  WHEN grade BETWEEN 7 AND 9   THEN 'middle'
  WHEN grade BETWEEN 10 AND 12 THEN 'high'
  ELSE NULL
END WHERE role = 'student' AND school_level IS NULL;
CREATE INDEX IF NOT EXISTS idx_users_school_level ON users(school_level);
```

#### (c) `portfolio_items` 컬럼 신규
```sql
-- 활동 발생 시점의 학교급 스냅샷 (학생이 진급해도 기록 보존, 검색용)
ALTER TABLE portfolio_items ADD COLUMN school_level TEXT;
-- 값 도메인: 'elementary' | 'middle' | 'high'
-- 신규 활동 등록 시 users.school_level에서 복사. 과거 데이터는 grade_year로 추정 후 일괄 보정.
CREATE INDEX IF NOT EXISTS idx_pi_user_period ON portfolio_items(user_id, school_level, activity_date);

ALTER TABLE portfolio_items ADD COLUMN teacher_comment TEXT;   -- 교사 코멘트 직접 보관 (없으면 observations에서 끌어옴)
ALTER TABLE portfolio_items ADD COLUMN content_image_url TEXT; -- 본인 산출물 대표 이미지
```

#### (d) 신규 테이블 `portfolio_reports`
```sql
CREATE TABLE IF NOT EXISTS portfolio_reports (
  id TEXT PRIMARY KEY,                    -- rpt_YYYY_MM_DD_xxxx
  user_id INTEGER NOT NULL,
  title TEXT NOT NULL,
  period_start DATE NOT NULL,             -- ★ 필수: 1단계 입력
  period_end DATE NOT NULL,               -- ★ 필수
  school_level TEXT NOT NULL,             -- ★ 필수: 'elementary'|'middle'|'high'
  options_json TEXT,                      -- 생성 옵션 보존 (재생성용)
  item_ids_json TEXT,                     -- 선택된 portfolio_item id 배열
  page_count INTEGER,
  file_path TEXT,                         -- data/reports/{userId}/{id}.pdf
  file_size INTEGER,
  status VARCHAR(20) DEFAULT 'ready',     -- pending|generating|ready|failed|expired
  share_token TEXT,                       -- 학생이 발급한 공유 링크 토큰 (옵션)
  share_expires_at DATETIME,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  expires_at DATETIME,                    -- 24h or null (영구 보관)
  FOREIGN KEY (user_id) REFERENCES users(id),
  CHECK(school_level IN ('elementary','middle','high'))
);

CREATE INDEX IF NOT EXISTS idx_pr_user ON portfolio_reports(user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_pr_token ON portfolio_reports(share_token);
CREATE INDEX IF NOT EXISTS idx_pr_filter ON portfolio_reports(user_id, school_level, period_start);
```

### 10-2. 접근성 (WCAG 2.1 AA 목표)
- 모달 진입 시 첫 인터랙티브 요소(닫기 버튼)에 자동 포커스, ESC로 닫기
- 단계 진행바: `role="progressbar"`, `aria-valuenow="1"`, `aria-valuemax="4"`
- 체크박스: `aria-label="분수의 덧셈 활동 선택"`, 키보드 Space 토글
- 페이지 썸네일: `role="button"`, `aria-label="3페이지로 이동"`
- 색 대비: 본문 #334155 on #fff = 12.6:1 (AAA), 메타 #6B7280 on #fff = 4.94:1 (AA)
- 진행 모달 스피너: `aria-busy="true"`, 스크린리더 음성 "PDF 만드는 중입니다"
- 다운로드 완료 토스트: `role="status"`, 자동 음성 "포트폴리오 PDF가 만들어졌어요"
