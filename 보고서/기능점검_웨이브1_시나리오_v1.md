### 0-2. 판정 기준
- **API 200 OK 만으로 PASS 금지.** 반드시 세 층을 모두 확인한다:
  1. **화면** — 실제 렌더된 텍스트/상태 (Playwright + `Read` 로 스크린샷 육안 확인)

  3. **DB** — 해당 테이블에 **행이 실제로 생겼는지**, 컬럼 값이 맞는지
- 세 층이 어긋나면 그 자체가 결함이다(가장 흔한 형태: 화면은 성공인데 DB 에 안 쌓임).
- **재진입·새로고침 후에도 상태가 유지되는지** 반드시 확인. 화면에서만 바뀌고 저장 안 되는 결함이 실제로 있었다(가짜 "배정됨" 버튼).

# 팀 1 — 수업 · 과제 · 평가 · 이수율 · 포트폴리오

교사가 올리고 학생이 하고 교사가 채점하는, **가장 자주 쓰이는 왕복**이다.

## T1-1. 수업 — 게시 → 학생 이수

**절차**
1. teacher1 → 채움클래스 → class1 → 수업 → **새 수업 만들기**
2. 제목·설명 입력, 콘텐츠 1개 이상 연결, 게시
3. student1 로 로그인 → 같은 클래스 → 수업 목록에 보이는지
4. 수업 열기 → 끝까지 진행 → **이수 처리**
5. teacher1 재로그인 → 이수 현황 확인

**확인**
- 화면: 학생 목록에 수업 노출 / 이수 후 상태 배지 변화 / 교사 화면의 이수 인원
- DB:
  - `lessons` — 행 생성, `class_id`, 게시 상태 컬럼
  - `lesson_contents` / `lesson_content_nodes` — 연결된 콘텐츠
  - `learning_logs` — 이수 시 `activity_type`(수업 이수 계열) 행 생성, `user_id`·`created_at`
- **실패로 볼 것**: 이수 눌렀는데 `learning_logs` 무행 · 새로고침 시 이수 상태 원복 · 교사 화면 인원과 실제 이수자 수 불일치

## T1-2. 과제 — 게시 → 제출 → 채점 → 피드백

**절차**
1. teacher1 → 과제 등록(마감일 포함)
2. student1 제출(첨부 포함), student2 는 **미제출로 남긴다**
3. teacher1 → 제출 목록 확인 → student1 채점(점수) + 피드백 작성
4. student1 재로그인 → 점수·피드백 열람

**확인**
- 화면: 교사 목록에 제출/미제출 구분 / 학생에게 점수·피드백 노출
- DB:
  - `homework` — 행, `due_date`
  - `homework_submissions` — student1 행 생성(`user_id`,`homework_id`, 제출 시각), student2 **무행**
  - `homework_feedback` — 피드백 행
  - 채점 점수 저장 위치 확인(`homework_submissions` 컬럼 또는 별도)
- **핵심 확인**: 채점 결과가 **학습 기록/성취에 반영되는가** — `learning_logs` 에 `achievement_code` 가 붙은 행이 생기는지. (PM 주: **이 지점이 "과제 채점 → 성취 반영 0" 로 이미 의심되는 곳**이다. 실제로 안 붙는다면 그 사실을 수치로 확정할 것)
- **실패로 볼 것**: 미제출자가 제출률 분모에서 빠짐 · 피드백이 학생 화면에 안 보임 · 채점했는데 성취 귀속 0

## T1-3. 평가 — 게시 → 응시 → 채점 결과

**절차**
1. teacher1 → 평가 등록(문항 포함) → **등록 즉시 학생에게 보이는지**(정책: 등록=active)
2. student1 응시·제출
3. 채점 결과가 학생·교사 양쪽에 어떻게 보이는지

**확인**
- DB: `exams`(상태 컬럼), `exam_students`(응시 행·점수), `exam_autosaves`
- 기간 게이트: 시작 전/종료 후 접근 시 동작
- **실패로 볼 것**: 등록했는데 학생 목록에 없음(과거 `draft` 하드코딩 버그 재발) · 점수 스케일 혼재(0~1 vs 0~100)

## T1-4. 클래스 대시보드 — 이수율 · 참여율

**절차**
1. T1-1~T1-3 을 마친 상태에서 클래스 대시보드/분석 화면 열기
2. 화면에 뜨는 **이수율·참여율의 분자/분모를 손으로 계산**해 대조

**확인**
- 분모가 **클래스 학생 수**인지, "활동한 학생 수"인지 명시적으로 확인
- 데모/탈퇴 계정이 분모에 섞이는지(`class_members` 대비 `users` 상태)
- **실패로 볼 것**: 분모가 화면마다 다름 · 미제출자가 분모에서 빠져 제출률이 100% 로 뜸

## T1-5. 과제 제출 → 포트폴리오 등록

**절차**
1. T1-2 의 student1 제출 직후, student1 포트폴리오 화면 확인

**확인**
- DB: `portfolios` / `portfolio_items` / `portfolio_attachments` 에 해당 제출이 등록되는지
- 자동 등록인지 학생이 직접 담아야 하는지 **설계 의도부터 코드로 확인**(자동이 아니면 그건 결함이 아니라 사양)
- **실패로 볼 것**: 자동 등록이 사양인데 행이 안 생김 · 등록됐는데 화면에 안 보임

# 팀 2 — 알림장 · 설문 · 게시판 · 갤러리 승인 · 콘테스트 · 쪽지 · 알림

## T2-1. 알림장
1. teacher1 작성(첨부 포함) → student1 열람 → 댓글/반응
2. DB: `notices`, `notice_comments`, `notice_reads`, `notice_reactions`, `notice_bookmarks`, `notice_drafts`
3. 확인: **읽음 처리**가 실제로 기록되는가 · 임시저장(draft)이 살아나는가
4. 실패: 읽음 인원이 실제 `notice_reads` 행수와 불일치

## T2-2. 설문
1. teacher1 설문 생성(익명 옵션 포함) → student1·student2 응답 → 교사 집계 확인
2. DB: `surveys`, `survey_responses`
3. 확인: **익명 설문에서 응답자 식별자가 노출되지 않는가** · 집계 분모가 클래스 학생 수인가 응답자 수인가
4. 실패: 익명인데 누가 뭘 냈는지 드러남 · `[object Object]` 표시

## T2-3. 일반게시판 — 글 · 댓글
1. teacher1·student1 각각 글 작성 → 서로 댓글 → 좋아요
2. DB: `class_boards`, `posts`, `comments`, `post_likes`
3. 확인: 댓글 작성/수정/삭제 · 권한(남의 글 수정 불가) · 새로고침 후 유지
4. 실패: 댓글이 화면에만 뜨고 `comments` 무행 · 남의 글 삭제 가능

## T2-4. 갤러리 + 나도예술가 — **승인 워크플로우** (중점)
1. student1 작품 업로드
2. **업로드 직후**: 갤러리 탭에 **본인에게도 안 보여야** 한다(정책: pending 은 "내 작품" 탭에서만 노출)
3. teacher1 또는 admin 승인 → 갤러리 탭에 공개
4. 반려 경로도 확인
5. DB: `student_gallery`(상태 컬럼), `gallery_attachments`, `gallery_comments`, `gallery_likes`, `gallery_views`, `gallery_reports`
6. 확인: 승인 전 다른 학생에게 노출 0 · 승인 후 즉시 노출 · 신고(report) 처리
7. 실패: pending 이 갤러리에 보임 · 승인해도 상태가 안 바뀜

## T2-5. 콘테스트
1. 진행 중 콘테스트 응모 → 마감 임박/마감 표시 → 결과
2. DB: `gallery_events`, `gallery_event_submissions`, `gallery_event_participants`
3. 확인: 마감 후 응모 차단 · D-day 표시 정확도

## T2-6. 소통쪽지
1. teacher1 → student1 쪽지 발송 → 수신 확인 → 답장
2. DB: `message_rooms`, `message_room_members`, `messages`
3. 확인: 읽음 표시 · 권한(제3자가 남의 방을 못 봄)

## T2-7. 알림(notifications)
1. 위 시나리오들을 수행하면서 `notifications` 테이블에 무엇이 언제 쌓이는지 추적
2. 확인: 알림이 생성되는 이벤트 목록 · 읽음 처리 · 사라지는 조건
3. 실패: 알림 벨은 있는데 아무것도 안 쌓임 · 남의 알림이 보임

# 팀 3 — 채움콘텐츠

## T3-1. 업로드 → 검토 → 관리자 승인 → 공개 (중점)
1. teacher1 로 영상 콘텐츠 업로드 · 문항 콘텐츠 업로드(각 1건)
2. **업로드 직후 상태**가 "검토 중"인지 DB 로 확인 — `contents` 의 상태 컬럼
3. 이 시점에 **공개 콘텐츠 목록에 노출되지 않아야** 한다(비로그인·타 사용자 양쪽에서 확인)
4. admin 로그인 → 승인 대기열에서 승인
5. 공개 전환 확인
6. DB: `contents`, `content_questions`, `content_content_nodes`, `channels`/`channel_posts`
7. 실패: 검토 단계 없이 즉시 공개 · 승인해도 공개 안 됨 · 반려 경로 없음

## T3-2. 풀기 · 담기 → 내 자료실 폴더
1. student1 이 공개 콘텐츠 **풀기**(문항 콘텐츠) → 결과 저장 확인
2. **담기** → 내 자료실에 추가
3. 내 자료실에서 **폴더 생성 → 콘텐츠를 폴더로 분류 → 이동/삭제**
4. DB: `content_attempts`, `content_progress`, `user_content_progress`, `content_collections`, `content_folders`, `user_learning_list`
5. 확인: 풀이 결과가 `content_attempts` 에 남는가 · 폴더 분류가 재진입 후 유지되는가
6. 실패: 담기 눌러도 목록에 없음 · 폴더 만들었는데 새로고침하면 사라짐

## T3-3. 검색
1. 콘텐츠 검색 — 제목/교과/학년/키워드
2. 전역 검색 컴포넌트(상단 돋보기)
3. DB: `suggested_keywords`, `suggested_kw_categories`
4. 확인: **검색 결과에 비공개/검토 중 콘텐츠가 섞이지 않는가**(권한 누수) · 한글 검색 정상 · 결과 0건일 때 안내
5. 실패: 검토 중 콘텐츠가 검색에 노출 · 한글 깨짐 · 결과 클릭 시 404

## T3-4. 파일 업로드 공통
1. 위 시나리오에서 쓰인 업로드 경로(과제 첨부·갤러리·콘텐츠·알림장)를 통해
2. 확인: 용량 제한 · 확장자 제한 · 업로드 실패 시 안내 · 다운로드 동작 · **남의 파일 URL 직접 접근 시 차단되는가**
3. DB/디스크: `uploads/` 하위에 실제 저장되는지, 경로가 DB 와 일치하는지
4. 실패: 확장자 무제한 · 남의 첨부 URL 로 직접 접근 가능
