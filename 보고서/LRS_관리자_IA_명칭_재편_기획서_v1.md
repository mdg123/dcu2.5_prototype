## 0. 핵심 요약 (Executive Summary)

사용자(교육청 평가자) 지적 = **"운영·리포트 탭이 무슨 인사이트를 주나? 메뉴명이 적절한가?"** 두 가지가 이번 재편의 축이다.

1. **'운영' 단어가 두 곳에서 다른 뜻으로 쓰인다.** '서비스 **운영** 진단'(a-svc-ops)이 *현황 분석* 탭에 있고, 별도로 '**운영**' 탭이 있다. 그런데 '운영' 탭의 실제 공통분모는 "데이터가 표준대로·결측 없이 수집되나 = **데이터 신뢰성**"이다. → **탭 '운영'→'데이터 신뢰성'으로 개명**하고, 뷰 '서비스 운영 진단'→'**서비스 활용 진단**'으로 다듬으면 **'운영'이라는 단어가 양쪽에서 사라져 중복이 소멸**한다. (뷰 이동 없음 = 회귀 최소.)
2. **'리포트' = 실제로는 '내보내기(raw CSV/xlsx)' 하나뿐** → 이름 과장. 도메인 전문가가 설계한 **8블록 요약 보고서**(신규 API 0, 기존 6개 엔드포인트 조립)로 `a-export`를 **제자리 승격**하고 내보내기는 그 하위 액션으로 흡수. 탭 '리포트' = 화면 '요약 보고서'로 정직화.
3. **명칭 전수 판정**: '표준체계 분석'(난해)→'수집 표준 점검', '교사 실행지수'(빈약)는 **표본 게이트 자동숨김**으로 통일, '활동×성취 교차'는 선택적 미세 정돈. 나머지(한눈 현황·지역별 성취수준 비교·학습시간 분석·데이터 품질)는 적절 → 유지.

**설계 원칙 = 인사이트 축과 건전성 축의 상위 분리.**
`현황 분석`(무엇이 일어나나: 활용·성취·시간) ↔ `데이터 신뢰성`(이 숫자를 믿어도 되나: 결측·표준·교사로깅). 국제 관행(KERIS 학습분석 / 1EdTech Caliper·xAPI 거버넌스)과 정합 — "성과 분석"과 "데이터 품질·표준 정합"을 별 축으로 관리.

**하위호환 보증**: 이 재편은 **라벨 문자열 + 카테고리 탭 라벨만** 바꾼다. **뷰 id·URL 해시·`category` 키·라우팅 맵(`MENU_TO_VIEW`·`LEGACY_MENU_TO_CATEGORY`·`ADMIN_VIEW_ALIAS`·`ROLE_CATEGORIES`)은 전부 불변**이다. `#a-svc-ops`, `?menu=operations` 등 기존 링크·북마크 100% 유효.

## 1. 현재 관리자 IA 실측 (4탭 · 9뷰) + 문제 지적

### 1-1. 렌더 메커니즘 (라벨이 사는 3곳)
FE는 `group` 필드를 **무시**하고 `category` 기준 **인페이지 가로 탭**으로 평탄화 렌더한다(`renderInPageTabs`, index.html:9389). 사용자가 보는 라벨의 출처는 3곳:

| 위치 | 무엇을 그리나 | 파일·지점 | 역할별 오버라이드 |
|---|---|---|---|
| **① 상단 GNB 2차 탭** (실제 클릭 대상) | 홈/현황 분석/운영/리포트 | `public/js/common-nav.js` sub[] (118~123) | `labelByRole` 지원(이미 student·teacher용 존재) |
| **② 브레드크럼 `bcMenu`** | "관리자 › **운영** › …" | `index.html` `MENU_LABELS`+`menuLabel()` (1355~1375) | `MENU_LABELS_STUDENT/TEACHER` 패턴 존재 |
| **③ 인페이지 뷰 탭 라벨** | 서비스 운영 진단/데이터 품질… | `index.html` `MENUS.admin[].label` (1311~1321) | 없음(역할별 배열이 분리) |
| (참고) `CATEGORIES[]` (1268~1273) | **렌더에 미사용**(ROLE_CATEGORIES만 소비) | index.html | 참조용 상수 |

> 시사점: 카테고리 탭 라벨을 **관리자만** 바꾸려면 ①의 `labelByRole`에 `admin:` 키 추가 + ②에 `MENU_LABELS_ADMIN` 오버라이드 신설이면 충분하다. **학생·교사 라벨은 건드리지 않는다**(회귀 0).

### 1-2. 현재 IA 트리
```
관리자 LRS
├─ 홈 (home)
│   └─ a-home          한눈 현황            [KPI8 + 8주추이 + 학교급 미니카드]
├─ 현황 분석 (analytics)
│   ├─ a-svc-ops       서비스 운영 진단      [서비스 사용률 랭킹·추세Δ·룰베이스 진단·취약기준]
│   ├─ a-macro         지역별 성취수준 비교   [격차 gap·CV·이중취약·우선개입·학교급×지역]
│   ├─ a-cross         활동×성취 교차        [3분위 매트릭스·산점도·활용집단 성취격차]
│   └─ a-time          학습시간 분석         [단위별 1인당 시간·요일×시간 히트맵]
├─ 운영 (operations)
│   ├─ a-quality       데이터 품질           [결측률·세션커버리지·동기화·서비스별 결측]
│   ├─ a-teacher-idx   교사 실행지수         [교사 실행지수 분포 히스토그램]
│   └─ a-xapi          표준체계 분석         [xAPI/AIDT 표준 정합·노드 히트맵] (표본<200 자동숨김)
└─ 리포트 (reports)
    └─ a-export        내보내기              [CSV/xlsx 원자료 다운로드 + 이력]
```

### 1-3. 문제 지적 (4가지)
- **[P1] '운영' 단어 분산·의미 충돌.** '서비스 **운영** 진단'은 *활용·정책*(사장/과열/급감 → 예산·홍보 판단) 성격인데 탭 이름 때문에 "운영 탭에 있어야 할 것 같은" 착시를 주고, 정작 '운영' 탭은 *데이터 신뢰성*(결측·표준)이라 **한 단어가 두 뜻**으로 쓰인다.
- **[P2] '리포트' 이름↔내용 불일치(과장).** 탭 이름은 정리된 보고서를 기대하게 하나 내용은 **원자료 반출 UI 하나뿐**. 필터 요약 KPI 4장 외 화면 인사이트가 사실상 0. 원자료 반출은 리포트가 아니라 리포트의 **부속 액션**.
- **[P3] 난해·빈약 뷰명.** '표준체계 분석'은 일반 관리자에게 무엇을 보는지 안 드러남(난해). '교사 실행지수'는 개념은 맞으나 시드 부족·산식 캡(100절단)으로 **빈 껍데기**라 신뢰를 깎음.
- **[P4] 상위 개념(인사이트 vs 건전성)이 탭 경계와 어긋남.** '서비스 운영 진단'(건전성 아님, 활용 인사이트)이 넘어가 있는 게 아니라 **이름만 건전성처럼 보여서** 축이 흐려진다. 이름을 성격에 맞추면 축이 선명해진다.

## 3. 재편 근거

### 3-1. 왜 A안(개명, 이동 없음)인가 — B안 기각
- **A안(채택)**: '운영'→'데이터 신뢰성' + '서비스 운영 진단'→'서비스 활용 진단'. 두 개명만으로 **'운영' 단어가 양쪽에서 사라져** 분산·충돌이 소멸. `a-svc-ops`는 현황 분석에 **그대로** 둔다.
- **B안(기각)**: `a-svc-ops`를 '운영' 탭으로 **이동**. → (1) **활용↔성취를 함께 봐야 하는데** '서비스 활용'(운영)과 '성취 격차'(현황)가 두 탭으로 갈라져 정책 판단이 분절. (2) `category` 재배정이 필요해 `MENU_TO_VIEW`·`LEGACY_MENU_TO_CATEGORY`·기본 랜딩까지 연쇄 수정 → **회귀 표면 증가**. A안은 라벨만 바꿔 이 리스크가 0.
- **결론**: 사용자 요구("운영 단어 정리")를 **이동이 아니라 정명(正名)**으로 달성 — 더 안전하고 의미도 선명.

### 3-2. 상위 개념 분리(인사이트 vs 건전성)의 정당성
- `현황 분석` = **활용(서비스 활용 진단) + 성취(지역별 비교·활동·성취 교차) + 시간(학습시간)** → 전부 "학습 현장에서 무엇이 일어나나". 정책 결정의 **재료**.
- `데이터 신뢰성` = **결측(데이터 품질) + 표준 정합(수집 표준 점검) + 교사 로깅(교사 활용 지수)** → 전부 "그 재료를 믿어도 되나". 판단의 **전제**.
- 이 분리는 국제 관행과 일치: KERIS 학습분석·1EdTech Caliper·xAPI 거버넌스는 "성과 분석"과 "데이터 품질/표준 정합"을 별 축으로 관리한다(도메인 전문가 §7).

### 3-3. '교사 활용 지수'가 데이터 신뢰성에 속하는지 (미세 이견 명시)
- 도메인 전문가 §3-1은 이 뷰를 △("신뢰성보다 '참여'에 가까움")로 표기. 엄밀히는 데이터 신뢰성보다 **교사 참여 건전성**이다.
- 그럼에도 데이터 신뢰성에 두는 이유: (a) §5 **표본 게이트로 자주 자동숨김**되므로 실제 노출 시 이 탭은 대개 '데이터 품질 + 수집 표준'만 보임 → 라벨이 잔여 콘텐츠에 정직, (b) 별도 탭 신설은 category 키 추가라 회귀↑. → **현 배치 유지 권장**. 만약 교사 지수를 상시 노출하기로 정하면 탭 라벨 대안 '데이터·참여 건전성' 고려(단, '운영' 단어는 재도입 금지).

### 3-4. 사용자(교육청 관리자) 탐색성 — 이름만으로 예측되는가
| 탭 | 관리자 질문 | 이름으로 예측되나 |
|---|---|---|
| 홈 | "전체가 살아있나?" | ✓ 한눈 현황 |
| 현황 분석 | "학습·서비스가 어떻게 돌아가나?" | ✓ (활용+성취+시간을 '현황'이 포괄) |
| 데이터 신뢰성 | "이 숫자를 믿어도 되나?" | ✓ 개명 후 명확(기존 '운영'은 모호했음) |
| 리포트 | "한 장으로 보고하려면?" | ✓ 내용 승격 후 정직 |
- **진입 기본 뷰(불변)**: 홈=`a-home`, 현황 분석=`a-svc-ops`(첫 탭·데이터 풍부, 튕김 없음), 데이터 신뢰성=`a-quality`(실데이터 충실, 표본부족 a-xapi로 안 튕김), 리포트=`a-export`(=요약 보고서). **모두 현재값 그대로** → 랜딩 회귀 0.
- **뷰 순서(불변)**: 각 탭 내 순서도 현재대로. 명칭만 바뀌므로 사용자의 위치 기억을 해치지 않음.

## 4. '리포트' 정직화 = 요약 보고서 (도메인 전문가 §4와 정합)

IA 관점의 요지만 정리(상세 콘텐츠 스펙·API 매핑은 도메인 전문가 검토서 §4가 정본):
- `a-export` 뷰를 **제자리 재설계** → **8블록 정책 브리프**: [헤더 표지밴드] → ① 기간 KPI → ② 참여·활용 하이라이트 → ③ 성취·격차 요약 → ④ 취약 성취기준 TopN → ⑤ 활동-성취 한 줄 → ⑥ 데이터 신뢰도 요약(상단 재노출) → ⑦ 자동 권고문 → ⑧ **근거 데이터 내보내기(접이식 details)**.
- **신규 백엔드 0**: 기존 `admin-kpi·service-ops·equity·weak-trend·cross-activity-achievement·dataset-coverage` **조립**만으로 성립.
- **IA 정합 포인트**: 리포트 탭에 뷰가 1개면 인페이지 탭 바가 렌더되지 않으므로(`items.length < 2`, index.html:9402), **탭 '리포트' = 화면 제목 '요약 보고서'**가 자연스럽게 정렬. 별도 하위 탭 불필요.
- **커플링 주의(Tier 2)**: `a-export` 라벨 '내보내기'→'요약 보고서' 변경은 **8블록 내용 재설계와 반드시 동시 배포**. 내용이 아직 내보내기 UI인 채로 라벨만 '요약 보고서'로 바꾸면 **반대 방향의 거짓말**이 된다.

## 5. 인사이트 부재 뷰 처리 — 표본 게이트 통일 (도메인 전문가 §5와 정합)

**원칙: "빈 껍데기 금지 · 표본 게이트로 통일 · 데이터 차면 자동 부활."**
