## 0. 왜 고치는가 (사용자 지적)

> "일부러 문제를 틀려서 이전 학년이나 학기로 이동하는 것은 좋아, 그러다가 **출발선을 확인해서 맞았음.**
> 그러면 이제는 진단결과를 제공하고 학습경로가 추천해야 하는데 **갑자기 원래 진단한 학년-학기의 문제가 나옴.**
> **진단이 언제 끝나는거야**"

조사 결과 — **v3 엔진에는 "출발선을 찾았다 → 종료" 조건이 아예 없다.**
v2/CAT 의 `_finalizeDiagNodeOutcome` 에는 전환 감지 조기종료(`endReason='position_found'`)가 있으나,
v3 전 구간에 대응 코드가 **한 줄도 없다.** v3 는 전환을 `branchVerdicts[unit]='pass'` 로 알고 있으면서
**진행 띠 라벨로만** 쓰고 종료에 쓰지 않는다.

원 단원 복귀는 `[P1 본류복귀 2026-06-11]` 로 명시된 **의도된 설계**다. 그 설계가 결함이다.

## 1. 사용자 확정 사양 (그대로 구현)

> ① **남은 갈래는 다 보되, 다 본 뒤엔 원래 단원으로 안 돌아가고 종료**
> ② **학습자가 중단을 원하면 물어봐야 함** — "진단 종료하고 결과를 볼래? 아니면 나중에 이어서 진단할래?"
> ③ **이때 결과를 보여주고, 학습이 필요한 실패한 단원을 학습경로로 보여줘야 함**
> ④ **거기서 학습할 수 있도록 해야 함**

추가 확정(선행 대화):
> ⑤ 우선순위 큐 정렬은 **1순위 높은 학년, 2순위 높은 학기** (목표에 가까운 선수부터)

## 2. 왜 "남은 갈래는 다 본다" 인가 — 설계 근거

큐에 함께 들어가는 선수 단원들은 **같은 것의 쉬운 버전이 아니라, 서로 다른 능력**이다.

> 두 자리 곱셈을 못 풀면 → 구구단 · 자릿값 · 받아올림이 함께 큐에 들어간다.
> **구구단을 맞혔다고 자릿값을 안다는 뜻이 아니다.**

따라서 **첫 통과에서 즉시 종료하면 출발선을 너무 높게 잡아** 학생이 곧 다시 막힌다.
같은 라운드의 갈래는 전부 확인한다. 단, 갈래마다 **표본(3문항 중 2정답)** 으로 판정하므로
갈래 3개여도 실제 문항은 10개 안쪽이다. (표본 로직은 이미 구현돼 있다 — `_v3SampleVerdict`)

---

## 3. 출발선 판정 기준 — **바뀐다**

| | 기준 |
|---|---|
| ❌ 잘못된 기준 | 통과한 것 중 **가장 높은** 단원 |
| ✅ 정본 | **실패한 것 중 근본도가 가장 낮은(=가장 쉬운) 단원** |

구구단 ○ / 자릿값 × / 받아올림 ○ 이면 **출발선은 자릿값**이다.
잘하는 것이 아니라 **못 하는 것 중 제일 근본**에서 시작해야 한다.

※ `getDiagnosisResultV3` 의 `recommendedStartNode` 가 이미 "가장 근본 미통과 개념"을 고르므로
   **이 기준은 기존 구현과 일치한다.** 새로 만들 필요 없이 그 값을 그대로 쓴다.

## 4. 종료 조건 (신설·수정)

### 4-1. 정상 종료 — 라운드 큐 소진
`_v3BranchSamplePass` 의 **"큐 소진 → 본류 복귀"** 지점에서,
**후퇴가 한 번이라도 있었다면**(`downCount > 0`) 본류로 복귀하지 않고 **종료**한다.

- `finished = true` · `sessionComplete = true` · `endReason = 'position_found'`
- `attemptStage = 'finished'` · `nextQuestion = null`
- 세션 `status = 'completed'`
- **`_v3RestoreOriginUnit` 호출 금지** (이게 사용자가 본 "원래 문제 재출제"의 원인)
- ⚠ `downCount === 0`(후퇴 없이 본류만 푼 경우)은 **기존 흐름 유지** — 하위호환 및 정상 완주 경로 보호

### 4-2. 바닥 도달 — 하향 자원 고갈
`branch:{type:'down', prereqConcept:null}` 은 **의미상 종료인데 지금 종료 플래그가 없다.**
`finished/sessionComplete` 를 세팅하고 `endReason='floor_reached'` 로 종료한다.
(현재는 모달만 띄우고 사용자가 안 누르면 세션이 `in_progress` 로 영구 잔존 — 미종료 세션 생성 경로)

### 4-3. 죽은 브레이크 되살리기
```js
// 현재: 본문이 빈 if 문 (죽은 코드)
if (!resp.finished && (st.diagnosedConcepts||0) >= DIAG_V3_CONCEPT_CAP && !resp.nextQuestion) { }
```
`DIAG_V3_CONCEPT_CAP = 30` 이 **한 번도 적용된 적 없다.**
→ **강제 종료가 아니라 §5 의 중단 확인 모달을 띄우는 트리거**로 연결한다.

### 4-4. 라운드 깊이 상한 무력화 수정
`_v3DownTo` 가 본류 재진입마다 `st.prereqRound = 1` 로 리셋해
`DIAG_V3_DOWN_DEPTH_CAP = 8` 이 사실상 작동하지 않는다. 리셋 대신 보존한다.
※ 4-1 이 들어가면 이 경로를 거의 타지 않으므로 **우선순위 낮음**.

## 5. 중단 확인 — 사용자 확정 ②③④

### 5-1. 언제 묻는가
1. 학생이 **진단 창을 닫으려 할 때**(모달 X · 뒤로가기 · 나가기 버튼)
2. **12분 경과**(`DIAG_SOFT_TIME_SEC = 720`) — 현재 v3 에서 **보고만 되고 집행 안 됨**. 이번에 연결한다.
3. **개념 30개 도달**(§4-3)

> 이 셋은 모두 "그만하고 싶을 만한 시점"이다. 강제 종료가 아니라 **묻는다.**

### 5-2. 무엇을 묻는가 — 2지선다

```
┌────────────────────────────────────────┐
│  여기까지 확인한 걸로 마칠까요?           │
│                                        │
│  지금까지 푼 것만으로도 어디서부터        │
│  공부하면 좋을지 알려줄 수 있어요.        │
│                                        │
│  [ 결과 보기 ]   [ 나중에 이어서 하기 ]   │
└────────────────────────────────────────┘
```

| 선택 | 동작 |
|---|---|
| **결과 보기** | 세션 `completed` + 결과 화면 + **실패 단원 학습경로** 즉시 제공 |
| **나중에 이어서 하기** | 세션 `in_progress` 유지 + **진짜 재개 가능**해야 함(§7) |

⚠ **"결과 보기"가 빈손이면 안 된다.** 한 문항이라도 풀었으면 그때까지의 실패 단원으로 경로를 만든다.
한 문항도 안 풀었으면 결과 대신 **"아직 결과를 만들 만큼 풀지 않았어요"** 안내 + 이어하기 유도.

### 5-3. UI 재사용
새 컴포넌트를 만들지 말 것. 이미 있는 모달 패턴을 따른다:
`showDiagV3UnitCompleteModal` · `showDiagV3DownModal` · `showSoftStopModal`(v2 용, 문구·구조 참고)
- 공통 UI 스케일 준수(본문 16px · 버튼 16px · 모달 헤더 19px)
- 주요 CTA 1개만 강조(`결과 보기`), `나중에`는 톤 다운
- 모바일(<768px)에서 버튼 세로 배치, 가로 스크롤 0

## 6. 큐 정렬 방향 — 사용자 확정 ⑤

### 현재 (오름차순 = 낮은 학년 먼저) — 뒤집어야 함
```js
cand.sort((a, b) => (_gradeAbsOf(a) - _gradeAbsOf(b)) || (_sortOrderOf(a) - _sortOrderOf(b)));
st.prereqQueue.sort((a, b) => (_gradeAbsOf(a) - _gradeAbsOf(b)) || ...);
```

`_gradeAbs` 는 **학년·학기를 한 축으로 합친 값**이다(초1-1=2 … 초6-2=13, 중1-1=14, 고3-2=25).
따라서 **비교 한 번으로 "1순위 학년, 2순위 학기"가 동시에 해결된다.** 별도 학기 비교 불필요.

### 바꿀 형태
```js
cand.sort((a, b) => (_gradeAbsOf(b) - _gradeAbsOf(a)) || (_sortOrderOf(b) - _sortOrderOf(a)));
```

### 절단은 손대지 않는다 — 정렬을 뒤집으면 저절로 옳아진다
`slice(0, N)` 은 **정렬된 배열의 앞**을 남긴다.
- 현재(오름차순): 앞 = 가장 낮은 학년 → **출발선 후보가 버려짐**
- 뒤집은 뒤: 앞 = 목표에 가장 가까운 선수 → **경계 후보가 남음**

잘린 깊은 노드는 사라지지 않는다 — 가까운 선수를 전부 실패하면
그 각각에서 다음 라운드 선수가 다시 파생된다(`nextRoundQueue`). **버리는 게 아니라 미루는 것.**

상한(`PREREQ_FANOUT=6` · `DOWN_CONCEPT_CAP=20`)의 **역할이 바뀐다**:
"어떤 후보가 살아남느냐"(잘못) → **"진단이 얼마나 길어질 수 있느냐"**(안전장치, 유지).

## 7. 결과·학습경로 누수 (사용자 확정 ③④의 전제)

### 7-1. 발견된 결함
FE 가 종료 시 `finishDiagV3(true)` 를 부르면 `POST /v3/:id/finish` 를 **건너뛴다.**
그런데 그 안에만 있는 두 가지가 통째로 누락된다:
- `_applyDiagnosisV3NodeResults` → `user_node_status.diagnosis_result` 기록
- `buildRecommendedPath` → `learning_paths` 영속

**실측: 완료된 v3 세션 18건 중 `learning_paths` 가 있는 것은 2건.
`user_node_status` 13행 중 10행이 `diagnosis_result IS NULL`.**

→ 사용자 요구 ③("결과를 보여주고 학습경로로") 자체가 **지금은 성립하지 않는다.**

### 7-2. 조치
- 종료 경로가 **반드시 `/finish` 를 타도록** 통일. 또는
- `GET /v3/:id/result` 진입 시 completed 인데 반영 흔적이 없으면 **1회 지연 복구**
  (`getRecommendedPathBySession` 의 지연 빌드와 동일 패턴 — 일관성 확보)

### 7-3. "이어서 진단 →" 이 재개가 아니다 — ②의 전제
```html
<!-- learning-map.html — 라벨은 "이어서", 동작은 새 세션 생성 -->
<button onclick="startDiagnosisV3Unit('...')">이어서 진단 →</button>
```
`startDiagnosisV3Unit` 은 `POST /v3/start` 다.
**"나중에 이어서 하기"를 제공하려면 이 버튼이 실제로 재개해야 한다.**
진짜 재개 경로(`resumeDiagV3FromServer` + `/v3/active`)는 현재 인트로 배너에서만 접근 가능.
→ 단원 CTA 도 `/v3/active` 를 먼저 조회해 같은 단원 세션이 있으면 재개로 보낸다.
   (BE `getV3Units` 가 `lastSessionId` 를 반환하지 않아 FE 의 "결과 보기" 버튼도 죽어 있다 — 함께 수정)
