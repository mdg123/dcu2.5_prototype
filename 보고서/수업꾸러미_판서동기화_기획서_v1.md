## 1. 설계 목표 & 비목표

### 목표
- 동기화 ON일 때 교사의 `#drawingCanvas` 획(stroke)을 **학생 화면에 거의 실시간(체감 ≤150ms)으로** 동일하게 표시.
- 교사·학생 **viewport 크기가 달라도 위치가 어긋나지 않음**(상대좌표).
- **늦게 입장/새로고침**한 학생도 현재 콘텐츠의 교사 판서를 복원.
- 콘텐츠 전환·전체지우기·지우개·형광펜 모두 동기화.
- 기존 lockstep 이벤트 계약(`lesson:sync:*`)과 **이름·권한·fail-open 패턴 일관**.

### 비목표 (이번 범위 제외 — §9 차기)
- 학생→교사 또는 학생 간 협업 판서(쌍방향). **이번은 단방향만.**
- 화이트보드 타입(`whiteboardDataMap`) 동기화.
- 판서 영구 저장(DB 영속) — 세션성 유지(동기화 종료 시 메모리 GC).
- undo/redo 동기화(교사 로컬 undo만, 학생엔 clear+재생으로 수렴은 차기).

## 2. 좌표 정규화 (핵심)

### 2.1 공식
교사 캔버스 크기 `Wt × Ht`, 학생 캔버스 `Ws × Hs`. 각 점을 **0~1 정규화**로 전송:

```
정규화 (교사 전송 시):
  nx = offsetX / canvas.width      // 0 ≤ nx ≤ 1
  ny = offsetY / canvas.height

역산 (학생 렌더 시):
  sx = nx * canvas.width           // 학생 자기 캔버스 폭
  sy = ny * canvas.height
```

> 근거: `resizeCanvas()`가 교사/학생 각자 viewport에 맞춰 `canvas.width/height`를 잡으므로(L2127-2128), 절대픽셀은 반드시 어긋난다. 비율 좌표만 viewport 독립.

### 2.2 선 두께 정규화 (검토 결과 → **상대화 채택**)
판서는 가로 폭 기준으로 시각 두께를 맞춘다. **폭 기준 정규화** 채택:

```
정규화:  nsize = penSize / canvas.width          // 전송
역산:    studentLineWidth = nsize * canvas.width  // 학생 폭으로 환산
```

- 근거: 텍스트·도형 위 강조선은 가로 비율을 따라가야 자연스럽다. 세로 기준이면 와이드 모니터에서 선이 가늘어 보임.
- **단, eraser·highlight 배수(`*5`, `*3`)는 역산 후 적용** — 즉 `nsize`로 환산한 `studentPenSize`에 동일 배수를 곱한다(픽셀 로직 100% 동일 유지). 의사코드 §3.5 참조.
- 트레이드오프: 폭만 정규화하면 극단적 종횡비 차이(예: 교사 가로 / 학생 세로 태블릿)에서 세로 위치는 맞아도 두께가 약간 두꺼워 보일 수 있음 → 허용(가독성에 유리). 양축 평균(`sqrt(W*H)`) 정규화는 과설계로 판단해 보류.

### 2.3 종횡비 불일치 처리
교사·학생 캔버스 종횡비가 다르면 정규화 좌표를 각자 폭/높이로 곱하므로 **그림이 약간 늘어남(stretch)**. 콘텐츠(영상/이미지/PDF)는 `object-fit:contain`이라 레터박스가 생길 수 있어 판서가 콘텐츠 밖 여백에 찍힐 수 있음.
- v1 정책: **stretch 허용**(단순·견고). 캔버스가 콘텐츠 영역 전체를 덮으므로 "교사가 화면 어디에 그렸나"의 상대 위치는 보존됨.
- v2 후보(§9): 콘텐츠 실제 렌더 박스(`getBoundingClientRect`) 기준 정규화로 레터박스 보정.

## 3. 이벤트 계약 (기존 `lesson:sync:*` 와 일관, 단방향 교사→서버→학생)

> 네이밍 규칙: 기존 `lesson:sync:start/move/end/state/peers`와 동일 네임스페이스. 신규 3종 추가.

### 3.1 교사 → 서버: 판서 세그먼트 배치

```
event: 'lesson:sync:draw'
payload: {
  classId,                  // number — 권한 재검증용
  lessonId,                 // string
  contentIndex,             // number — 어느 콘텐츠에 그렸는지 (서버 currentIndex와 교차검증)
  tool,                     // 'pen' | 'highlight' | 'eraser'
  color,                    // '#rrggbb' (eraser면 무시)
  nsize,                    // number 0~1 — 폭 정규화 두께 (penSize/Wt)
  segments: [               // 한 배치 분량의 연속 선분들 (정규화 좌표)
    { x0, y0, x1, y1 },     // 0~1 each. (x0,y0)=이전점 (x1,y1)=현재점
    ...
  ],
  strokeId                  // string — 같은 stroke 식별 (디버깅/순서 보정용, 선택)
}
```

- **배치 전략(채택)**: `draw()` 콜백마다 점을 버퍼에 모았다가 **rAF 또는 60~100ms 타이머**로 flush. stroke 종료(`stopDrawing`) 시 남은 버퍼 즉시 flush + `strokeEnd:true` 1회.
  - 근거: stroke 단위 전송(대안)은 긴 획에서 학생이 "획이 끝나야 한 번에 보임" → 지연 체감 큼. 점 단위 직송(대안)은 패킷 폭주. **부분 배치(~75ms)**가 부드러움/대역의 균형점.
  - 트레이드오프 명시: 75ms 배치는 학생이 교사 손끝보다 한 박자(≤150ms) 늦게 따라온다. 강의 판서엔 충분. 더 부드럽게 하려면 50ms로 조이되 모바일 대역 주의.

### 3.2 교사 → 서버: 판서 지우기 (전체/콘텐츠 전환)

```
event: 'lesson:sync:draw-clear'
payload: { classId, lessonId, contentIndex }
```
- 트리거: 교사가 툴바 "전체 지우기"(`clearDrawing` L2203) 클릭, **또는** 콘텐츠 전환(`selectContent` L1175의 `clearDrawing` 직후) 시 해당 contentIndex 판서 무효화.

### 3.3 서버 → 학생: 판서 적용 (실시간 브로드캐스트)

```
event: 'lesson:sync:annotation'
payload: {
  contentIndex,
  op: 'segments' | 'clear' | 'snapshot',
  // op==='segments':
  tool, color, nsize, segments:[...],
  // op==='clear': (추가 필드 없음)
  // op==='snapshot' (늦은 입장 복원):
  strokes: [ { tool, color, nsize, segments:[...] }, ... ]   // contentIndex 누적 전체
}
```
- **단일 채널화**: 실시간 세그먼트(`op:'segments'`), 지우기(`op:'clear'`), 복원 스냅샷(`op:'snapshot'`)을 **하나의 이벤트**로 통합 → FE 핸들러 1개로 단순화(기존 `lesson:sync:state` 단일화 철학과 동일, L474 주석 참조).

### 3.4 서버 처리 규칙
1. **권한 재검증**: `lesson:sync:draw`/`draw-clear` 수신 시 `canControlLesson(userId, classId, lessonId)` 호출 → false면 `emitLessonError` 1회 후 **무시**(L479 패턴 재사용).
2. **컨트롤러 본인만**: `sync.on && sync.controllerId === userId` 아니면 무시(move와 동일 가드, L602).
3. **contentIndex 일치 검증**: payload `contentIndex !== sync.currentIndex`면 무시(교사가 이동 직후 직전 콘텐츠 stroke가 새 콘텐츠에 찍히는 사고 방지). 약간의 race는 §6.1에서 처리.
4. **배치 throttle(가벼움)**: draw는 클라가 이미 75ms 배치하므로 서버는 **per-stroke가 아닌 per-socket 1초당 N회 상한**(예: 20 batch/s)만 가드 — 폭주 학생 주입 방어. 정상 교사 트래픽은 통과.
5. **누적 후 즉시 브로드캐스트**: `io.to('lesson:'+lid).emit('lesson:sync:annotation', {op:'segments',...})`. (교사 본인 echo는 학생 렌더 분기에서 무시 — §5)

### 3.5 학생 렌더 의사코드 (픽셀 로직 동일)

```js
function renderRemoteStroke({ tool, color, nsize, segments }) {
  const W = canvas.width, H = canvas.height;
  const lw = nsize * W;                       // 폭 역산 (§2.2)
  // ── draw() L2138-2158 과 동일 분기 ──
  if (tool === 'eraser') {
    ctx.globalCompositeOperation = 'destination-out';
    ctx.lineWidth = lw * 5;
  } else if (tool === 'highlight') {
    ctx.globalCompositeOperation = 'source-over';
    ctx.strokeStyle = color; ctx.lineWidth = lw * 3; ctx.globalAlpha = 0.3;
  } else { // pen
    ctx.globalCompositeOperation = 'source-over';
    ctx.strokeStyle = color; ctx.lineWidth = lw; ctx.globalAlpha = 1;
  }
  ctx.lineCap = 'round'; ctx.lineJoin = 'round';
  for (const s of segments) {
    ctx.beginPath();
    ctx.moveTo(s.x0 * W, s.y0 * H);
    ctx.lineTo(s.x1 * W, s.y1 * H);
    ctx.stroke();
  }
  ctx.globalAlpha = 1; ctx.globalCompositeOperation = 'source-over';   // 원복(stopDrawing L2160-2164)
}

socket.on('lesson:sync:annotation', (m) => {
  if (isTeacherViewer) return;                 // 교사 본인 echo 무시 (자기 캔버스엔 이미 그려짐)
  if (m.contentIndex !== syncState.index) return; // 다른 콘텐츠용이면 무시(전환 race 방지)
  if (m.op === 'clear') { ctx.clearRect(0,0,canvas.width,canvas.height); annotBuffer=[]; return; }
  if (m.op === 'snapshot') {                    // 늦은 입장 복원
    ctx.clearRect(0,0,canvas.width,canvas.height);
    annotBuffer = m.strokes.slice();
    m.strokes.forEach(renderRemoteStroke);
    return;
  }
  // op === 'segments'
  annotBuffer.push({ tool:m.tool, color:m.color, nsize:m.nsize, segments:m.segments });
  renderRemoteStroke(m);
});
```
- `annotBuffer`: 현재 contentIndex 누적 stroke. **resize 시 재적용**(§6.3)·콘텐츠 전환 복원에 사용.

## 4. 서버 상태 구조

### 4.1 lessonSync 엔트리 확장 (기존 §2.1 구조에 필드 추가)

```
lessonSync.get(lid) = {
  on, controllerId, controllerName, classId, currentIndex, members(Map), updatedAt,   // 기존 유지
  // ── 신규: 판서 누적 (contentIndex별) ──
  annotations: Map<contentIndex, Array<{tool,color,nsize,segments:[{x0,y0,x1,y1}]}>>
}
```

### 4.2 누적 전략 (세그먼트 누적 vs dataURL 스냅샷 — **세그먼트 누적 채택**)

| 방식 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **세그먼트 누적(채택)** | 정규화 좌표라 **resize·viewport 독립 복원**, 텍스트 경량, 학생별 자기 폭 렌더 | 장시간 누적 시 메모리 증가 → **stroke 상한·콘텐츠 전환 시 GC로 억제** | ✅ |
| dataURL 스냅샷 | 복원 1패킷 | 교사 해상도 고정 비트맵 → 학생 폭 다르면 흐림/늘어남, base64 수십~수백KB 대역 폭증 | ❌ |

- **메모리 가드**: contentIndex별 누적 stroke 수 상한(예: 4,000 세그먼트) 초과 시 **가장 오래된 stroke부터 드롭**(또는 자동 `draw-clear` 권고 토스트). 콘텐츠 전환·동기화 종료 시 `annotations` 비움.
- **드롭 트레이드오프**: 상한 도달 시 늦은 입장 학생은 일부 초반 판서가 누락될 수 있음 → 실강의에선 콘텐츠당 stroke가 수십~수백 수준이라 거의 미발생. 상한은 안전망.

### 4.3 늦은 입장/새로고침 복원
- `lesson:join`(L488) 처리 끝에서, **sync.on && 비교사뷰**면 현재 `currentIndex`의 `annotations`를 모아 **그 소켓에만** `lesson:sync:annotation {op:'snapshot', contentIndex, strokes}` push.
  - 기존 join이 이미 `lesson:sync:state`로 위치 복원하므로, 그 직후 판서 스냅샷 1패킷 추가.
- 교사뷰(`canControl`)에는 스냅샷 미전송(교사는 자기 로컬 캔버스 사용).

### 4.4 GC / 정리
- `lesson:sync:end`·교사 `disconnect`(L712~) 시 `annotations` 정리 정책은 §6.5.
- 1시간 sweep(L764)에서 `members.size===0`이면 엔트리째 삭제 → `annotations`도 함께 소멸(추가 작업 불필요).

## 5. 학생 측 동작 (읽기전용 일관)

1. **학생 캔버스 표시 모드**: 현재 `.drawing-canvas`는 `.active`(도구 선택)일 때만 보인다(opacity/pointer-events). 동기화 ON 학생은 도구를 안 켜도 교사 판서가 보여야 하므로 **신규 CSS 클래스 `.sync-view` 추가 설계**:
   ```css
   .drawing-canvas.sync-view { opacity: 1; pointer-events: none; }  /* 보이되 입력 차단 */
   ```
   - sync ON + 비교사뷰 → `canvas.classList.add('sync-view')`. OFF → 제거.
2. **학생 자기 판서 입력 차단**: sync ON + 비교사뷰 동안 툴바(펜/형광펜/지우개/전체지우기) **비활성(disabled + dim)**. 이미 잠금 배너(L731 `#syncLockBanner`)·이동 잠금(L2402 `prevBtn/nextBtn.disabled`)이 있으므로 **같은 잠금 상태에 편승** — `applyLockUI(true)` 안에서 `deactivateTools()` 호출 + 툴바 `aria-disabled`.
   - 근거: 동기화 중엔 "교사 판서만" 노출(요구사항). 학생 로컬 낙서가 교사 판서 위에 섞이면 혼란.
3. **콘텐츠 이동 동기화**: 교사가 `lesson:sync:state` index 변경 → 학생 `selectContent(idx)` 이미 처리(L2319). 그 직후 **캔버스 클리어 후 새 contentIndex의 `annotations` 적용**. `selectContent`의 `clearDrawing()`(L1175) 다음에 `applyAnnotationsForIndex(idx)` 훅 1줄 추가:
   ```js
   if (syncState.on && !isTeacherViewer) {
     ctx.clearRect(0,0,canvas.width,canvas.height);
     // 서버가 join/state 후 snapshot을 push하거나, 로컬 annotBuffer가 해당 idx면 재적용
   }
   ```
   - 권장: 콘텐츠 전환 시 **학생이 서버에 `lesson:sync:annotation` snapshot을 재요청**하기보다, 서버가 `lesson:sync:move` 브로드캐스트에 이어 **새 index의 snapshot을 룸에 함께 push**(전체 학생 동일) → 왕복 절약.
4. **sync OFF / 교사 이탈 시 판서 정리** → §6.5 정책.
5. **학생 원래 자기 판서와의 관계**: 일반(비동기화) 모드에서 학생은 자기 도구로 자기 캔버스에 그릴 수 있음(기존 동작 유지). **동기화 ON이 되는 순간 학생 로컬 판서는 클리어**하고 교사 판서로 전환, OFF 되면 다시 자기 도구 사용 가능(빈 캔버스에서 시작). "동기화 중엔 교사 판서만" 원칙 고수.

## 6. 엣지 케이스 & 성능

| # | 케이스 | 처리 |
|---|---|---|
| 6.1 | **콘텐츠 전환 race** (교사가 이동 직후 직전 콘텐츠 잔여 stroke 도착) | 서버 `contentIndex !== sync.currentIndex`면 draw 무시(§3.4-3). 학생도 `m.contentIndex !== syncState.index` 무시(§3.5). 이중 가드 |
| 6.2 | **대량 세그먼트 폭주** | 클라 75ms 배치 + 서버 per-socket batch rate 상한(20/s) + contentIndex별 stroke 상한(4,000 세그먼트, FIFO 드롭) |
| 6.3 | **학생/교사 resize** | 정규화 좌표라 재계산 가능. `resizeCanvas()`(L2124)에 훅: sync 학생은 resize 후 `ctx.clearRect` → `annotBuffer.forEach(renderRemoteStroke)` 재적용. 교사는 자기 캔버스(원래대로) |
| 6.4 | **하이라이트/지우개 동기화** | `tool` 필드로 학생이 동일 분기(§3.5). 지우개는 `destination-out`이라 학생 캔버스의 **교사 판서만** 지움(콘텐츠 iframe/이미지는 별 레이어라 안전) |
| 6.5 | **sync OFF / 교사 이탈 정리** | **정책 채택: 즉시 클리어**. `lesson:sync:end` 또는 `teacher-left`(L722) 수신 시 학생 `ctx.clearRect` + `annotBuffer=[]` + `.sync-view` 제거 + 툴바 재활성. (대안 "고정 보존"은 교사가 사라졌는데 판서만 남아 혼란 → 기각. 단 OFF 배너 "이제 자유롭게 이동" L2415와 함께 "선생님 판서가 사라졌어요" 1.2초 토스트) |
| 6.6 | **멀티탭 교사** | 기존 `members`는 userId 단위(L529), disconnect는 같은 userId 다른 탭 살아있으면 유지(L705-709). 판서도 controllerId(userId) 기준이라 **어느 탭에서 그리든 동일 controllerId** → 자연 동작. 단 두 탭 동시 그리기는 last-writer 누적(둘 다 같은 contentIndex면 합쳐짐) — 실사용 희박, 허용 |
| 6.7 | **늦은 입장 비용** | 세그먼트 스냅샷(정규화 텍스트). 콘텐츠당 수백 stroke면 수~수십KB(JSON gzip). dataURL(수백KB) 대비 경량(§4.2). 상한으로 최악도 bounded |
| 6.8 | **소켓 미로드/실패** | 기존 fail-open(L2236 `!window.io` 시 자유 이동) 그대로. 판서도 동기화 비활성 시 미동작 — 안전 |
| 6.9 | **교사가 sync OFF인데 판서** | OFF면 `sync.on=false`라 서버가 draw 무시(§3.4-2). 교사 로컬 캔버스에만 그려지고 학생 전파 안 됨(정상 — 동기화 중에만 공유) |
| 6.10 | **권한 박탈 race** (교사가 멤버에서 제거된 직후) | 매 draw마다 `canControlLesson` DB 재검증(§3.4-1)이라 즉시 차단 |

## 7. UX 설계 (공통 스케일 준수 · 가로스크롤 0)

### 7.1 학생 화면 "선생님 판서 표시 중" 피드백
- **결론: 별도 큰 배지 불필요. 기존 잠금 배너(`#syncLockBanner` L731) 문구만 보강**으로 충분.
  - 잠금 ON 문구(L2398): `"선생님 화면을 따라가고 있어요 · 이동이 잠겨 있어요"` →
    교사가 판서를 시작하면(첫 stroke 수신 시) **`· ✏️ 판서 표시 중`** suffix 추가(같은 배너, 줄바꿈 없이). 판서 없으면 미표시.
  - 근거: 새 UI 요소를 늘리면 화면 혼잡. 이미 "따라가는 중" 맥락이 있어 판서도 그 일부로 자연 인지. (a)진입·(b)현재상태·(c)복귀 동선이 한 배너에 응축.
- **미세 표시 대안(선택)**: 우상단 툴바 영역에 작은 펜 펄스 아이콘(13px, `--c-primary`) — 단 GNB·닫기 안전영역 침범 금지. v1은 배너 suffix만, 펄스는 차기.

### 7.2 교사 화면
- 교사 도구(펜/형광펜/지우개/색/굵기)는 **그대로**. 추가 UI 없음. 동기화 ON이면 그리는 즉시 전파(투명).
- 교사 헤더 `#syncToggleBtn`(L2332) "동기화 중 · N명"은 유지 — 판서도 그 N명에게 감(별도 표시 불요).

### 7.3 스케일·반응형
- 신규 텍스트(배너 suffix·토스트)는 **본문 16px / 메타 13~14px** 공통 스케일 준수(CLAUDE.md UI 공통 스케일).
- 캔버스는 viewport 100% 오버레이라 **가로스크롤 유발 없음**. 모바일(<768px)에서도 `inset:0`이라 안전.

## 8. 보안

1. **모든 draw/clear 서버 재검증**: `canControlLesson(userId, classId, lessonId)` (owner/co_teacher + lesson↔class 교차검증 또는 admin). 클라 `isTeacher` 신뢰 금지(L42-43 원칙).
2. **컨트롤러 본인만**: `sync.controllerId === userId` 아니면 무시.
3. **학생/비멤버 주입 차단**: `lesson:join` 멤버십 검증(L494) 통과해야 룸 입장. 룸 밖 소켓의 draw는 룸 미수신. 룸 안 학생이 `lesson:sync:draw`를 위조 emit해도 `canControlLesson`=false → `emitLessonError` 후 무시. **학생 emit은 절대 룸 브로드캐스트되지 않음.**
4. **contentIndex 위조**: 교차검증(§3.4-3)으로 타 콘텐츠 오염 차단.
5. **payload 검증**: `segments`는 배열·길이 상한(예: 배치당 ≤500점)·각 좌표 `0≤v≤1` 클램프. 초과·비정상은 드롭. `tool`은 화이트리스트(pen/highlight/eraser)만.
6. **DoS 가드**: per-socket batch rate 상한(§3.4-4) + stroke 누적 상한(§4.2).
