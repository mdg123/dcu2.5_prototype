## 6. 시나리오 개선 제안

본 절에서는 소스·시나리오 문서 수정 없이 의견만 기록합니다.

1. **node_modules 사전 준비 절차 명시 필요**  
   시나리오 문서 0.2절의 `npm install` 지시와 QA 에이전트 절대 규칙의 `npm install 금지` 간 충돌이 존재합니다. 이번이 2번째 fresh-container 실행 사이클이며, 매 실행마다 node_modules가 없는 상황이 재현됩니다. 가능한 해결책:
   - **방안 A**: QA 에이전트를 기동하는 SessionStart hook에서 `npm install` 사전 실행 (QA 에이전트 자신은 실행 안 해도 됨).
   - **방안 B**: QA 절대 규칙에 "SessionStart hook 또는 컨테이너 준비 단계의 npm install은 소스 수정이 아닌 환경 준비로 허용" 예외 조항 추가.
   - **방안 C**: node_modules 포함 Docker 이미지 또는 cache 레이어 사용.

2. **Preview MCP 탑재 여부 사전 확인 절차 추가 권장**  
   시나리오 문서는 Preview MCP를 기본 검증 수단으로 규정하지만, 실행 환경에 따라 미탑재될 수 있습니다. 0.4절에 "Preview MCP 존재 여부 확인 → 없으면 전체 UI 검증 BLOCKED로 명시" 흐름을 추가하면 실행 시 혼선을 줄일 수 있습니다.

3. **`db/dachaeum.db` vs `data/dacheum.db` 경로 불일치 수정 권장**  
   시나리오 문서 0.4절의 DB 경로가 `db/dachaeum.db`(Windows 경로 기반)인데 실제 서버는 `data/dacheum.db`를 사용합니다. 이 불일치로 매번 확인 혼선이 발생합니다.

4. **조기 종료 시 점검 주기 단축 알림 메커니즘 권장**  
   전체 BLOCKED가 발생했을 때 PM에게 즉시 알림(Slack/이메일 등)을 보내는 절차가 없습니다. 보고서 커밋만으로는 다음 날 09:30까지 인지가 늦어질 수 있습니다.
