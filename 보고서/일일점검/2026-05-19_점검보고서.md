### BUG-20260519-01

- **우선순위**: P0 Critical
- **시나리오**: S02 (서버 기동 단계)
- **모듈**: 공통 (schema migration)
- **제목**: 서버 시작 불가 — `primary_node_id` 컬럼 누락 크래시
- **재현 단계**:
  1. 신규 환경에서 `npm install` 후 `node server.js` 실행
  2. `initSchema()` → `initCurriculum()` 순서로 실행
  3. `lib/xapi/std-resolver.js` 모듈 로드 시 `SqliteError: no such column: primary_node_id` 발생하며 프로세스 종료
- **기대 결과**: 서버가 port 3000에서 정상 기동, HTTP 200 반환
- **실제 결과**: 서버 exit code 1, 다음 오류 발생:
  ```
  SqliteError: no such column: primary_node_id
      at Database.prepare (.../better-sqlite3/lib/methods/wrappers.js:5:21)
      at Object.<anonymous> (.../lib/xapi/std-resolver.js:48:23)
  ```
- **첨부**:
  - HTTP 응답: 서버 기동 불가 (curl 결과: `000`)
  - 콘솔 로그: `[다채움] 교육과정 표준체계/xAPI 스키마 초기화 실패: ALTER TABLE curriculum_standards... (table doesn't exist at migration time)`
- **추정 원인**: `db/schema.js` L1339~1346의 `curriculum_standards` ALTER TABLE이 try-catch(L1390)로 감싸져 있어, `curriculum_standards` 테이블이 아직 생성되기 전인 시점에 실행되면 오류를 무시하고 넘어감. 이후 `db/curriculum.js`의 `initCurriculum()`이 `CREATE TABLE IF NOT EXISTS curriculum_standards` 로 테이블을 생성하지만 이미 ALTER TABLE 실패로 `primary_node_id` 컬럼이 없음. `std-resolver.js`는 모듈 로드 시점에 `SELECT ... primary_node_id FROM curriculum_standards` prepare를 실행하여 충돌
- **영향 범위**: 신규 환경 구축 시 서버 기동 불가 (전체 서비스 영향)
- **권장 처리**: `db/schema.js`의 `curriculum_standards` ALTER TABLE 이전에 `initCurriculum()`을 선 실행하거나, `std-resolver.js`의 prepare를 lazy 방식으로 변경. 또는 `db/curriculum.js`의 `CREATE TABLE` 정의에 `primary_node_id TEXT` 컬럼을 포함시킴.

## 관찰 메모

1. **스키마 마이그레이션 일관성 부재**: 6개 테이블에서 총 15개 이상의 컬럼이 누락되어 있어, `db/schema.js`의 마이그레이션 코드와 `db/*.js` 비즈니스 로직 코드 사이에 심각한 불일치가 있음. 신규 환경 구성 시 반드시 수동 ALTER TABLE이 필요한 상태.

2. **서버 기동 순서 의존성**: `initSchema()`와 `initCurriculum()`의 호출 순서 문제로 `curriculum_standards` 컬럼이 생성되지 않는 버그가 있음. 두 함수의 의존성을 명확히 해야 함.

3. **평가 채점 버그 영향 범위**: `routes/exam.js`의 `q.answer` vs `q.correct_index` 불일치로 모든 CBT 평가 점수가 0이 됨. 기존 운영 데이터의 exam_students.score 값을 재검토 필요.

4. **S14 LRS 데이터**: 본 점검 시나리오 실행으로 생성된 39건의 활동 로그가 정상적으로 LRS에 집계됨. avg_score=0 (CBT 버그 영향).
