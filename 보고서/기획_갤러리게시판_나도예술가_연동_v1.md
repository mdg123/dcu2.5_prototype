## 0. 발단 — 사용자 지적

> "왜 채움클래스에서 게시판 갤러리로 이미지를 올렸는데 **나도예술가에는 해당 이미지가 공유되지 않고 단지 빈 이미지로만** 나오는지"

---

## 1. 의도된 설계 (사용자 확정)

> "채움클래스에서 **갤러리 게시판 생성 시**, 게시물을 업로드하면 이걸 **나도예술가 게시판에 업로드할지도 설정**하고,
> 만약 그렇게 세팅하면 게시물 승인을 **클래스 개설자**가 하면 해당 게시물의 **이미지 및 동영상, 음원 등**은
> 나도예술가로 연결되어 표시하는 것"

```
게시판 생성  →  [나도예술가 연결] 설정 (게시판 단위)
                        ↓ (켜져 있으면)
학생이 게시물 업로드  →  개설자 승인  →  나도예술가에 표시
                                          이미지·동영상·음원 전부
```

---

## 2. 현재 구현과의 차이 — 실측

### ① 🔴 게시판 단위 설정이 **없다**
`class_boards` 컬럼: `id · class_id · name · board_type · requires_approval · description · sort_order · is_active · created_at`
→ **나도예술가 연결 여부를 저장할 칸이 아예 없다.**

대신 `routes/board.js:130` 이 이렇게 판단한다:
```js
const shouldShareToGallery = (req.body.shareToGallery === true)     // 글마다 체크박스
  || (postData.category === 'gallery');                             // 갤러리 게시판이면 무조건
```
- **게시판 단위가 아니라 글 단위 체크박스**
- 게다가 갤러리 게시판이면 **체크와 무관하게 자동** → **끄는 방법이 없다**

### ② 승인 주체는 정상 ✅
`routes/board.js:312` — `if (req.myRole !== 'owner') return 403 '개설자만 승인할 수 있습니다.'`
**클래스 개설자만 승인.** 의도대로이므로 **건드리지 않는다.**

### ③ 🔴 이미지 1개만 넘어간다 — 동영상·음원 누락
연동부(생성 `:138`, 승인 백필 `:334`) 둘 다:
```js
image_url: post.image_url || '/images/placeholder.png'
```
**단일 `image_url` 뿐.** 그런데 나도예술가에는 **`gallery_attachments`**(18행)가 있고
`id · gallery_id · type · url · mime · file_name · file_size · sort_order` 로 **여러 미디어를 담게** 돼 있다.
`public/plus/gallery.html:1980` 도 *"attachments 결정: API 응답 우선, 없으면 image_url 단일로 fallback"* 이라 **받을 그릇은 이미 있다.**
→ **그릇은 있는데 게시판이 안 채운다.**

### ④ 🔴 빈 이미지의 직접 원인 — 이미지 넣는 길이 둘인데 하나만 본다
게시판에서 이미지를 넣는 방법이 두 가지다:
1. **파일 선택 / 촬영** → `/api/upload?type=board` 업로드 → `image_url` 에 담김
2. **본문 에디터(Quill)에 직접 삽입** → `content` 안의 `<img>` 로만 존재

게시판 목록은 **둘 다** 본다 (`class-home.html:4354`):
```js
const thumb = p.image_url || extractFirstImage(p.content) || extractYoutubeThumbnail(p.content);
```
**연동은 ①만 본다** → 본문에 넣으면 `placeholder.png` 로 대체된다.
**게시판에서는 정상으로 보이고 나도예술가에서만 빈 이미지**가 되는 이유가 이것이다.

## 3. 구현 범위

### 3-1. `class_boards` 에 연결 설정 추가
- 컬럼 신설(예: `share_to_gallery INTEGER DEFAULT 0`). **마이그레이션은 `db/schema.js` 의 기존 `ALTER TABLE` 패턴**을 따를 것(`:2061` 참고).
- **게시판 생성·수정 화면**에 설정 노출. `board_type='gallery'` 일 때만 의미가 있으므로 그때만 보이게 한다.
- 기본값 판단: 기존 갤러리 게시판들이 지금은 **자동 연동**되고 있다. 기본을 `0`(꺼짐)으로 두면 **기존 동작이 조용히 바뀐다.**
  → 기존 행은 `board_type='gallery'` 면 `1` 로 백필하고, **신규 생성 기본값은 화면에서 명시적으로 고르게** 한다. 판단 근거를 보고할 것.

### 3-2. 글 단위 자동 연동 제거
```js
// 현재 — 끄는 방법이 없다
shouldShareToGallery = req.body.shareToGallery === true || postData.category === 'gallery'

// 정본 — 게시판 설정이 유일한 기준
shouldShareToGallery = (그 글이 속한 class_boards.share_to_gallery === 1)
```
- 글마다 뜨는 체크박스(`#shareToGallery`)는 **제거하거나**, 게시판 설정이 켜진 경우에만 "이 글은 제외" 용도로 남길지 판단. **단순한 쪽을 권장.**
- `board_id` 가 없는 레거시 글의 처리 방침을 정하고 보고할 것.

### 3-3. 이미지·동영상·음원 전부 연동
- 승인 시 `gallery_attachments` 를 채운다. `type`·`mime`·`sort_order` 를 채워야 나도예술가가 제대로 렌더한다.
- 수집 대상:
  1. `post.image_url`(파일 선택 업로드)
  2. **본문 `content` 안의 `<img>`·`<video>`·`<audio>`·`<source>`** — 게시판이 쓰는 `extractFirstImage` 와 같은 방식이되 **첫 개만이 아니라 전부**
  3. 게시글에 첨부 개념이 따로 있으면 그것도
- 대표 이미지(`student_gallery.image_url`)는 **첫 이미지 attachment** 로 세운다(`gallery.html:2546` 이 이미 그 규약을 쓴다).
- **이미지가 하나도 없으면** `placeholder.png` 로 채우지 말고 **어떻게 할지 정한다** — 지금은 빈 이미지가 갤러리에 올라간다. 후보: 연동 자체를 건너뛰기 / 텍스트 작품으로 표시. 판단 근거를 보고할 것.

### 3-4. 기존 데이터 보정
`student_gallery` 에서 `image_url` 이 placeholder 인데 **원본 글 본문에는 이미지가 있는** 건을 되살린다.
⚠ 정본 DB write — rollback SQL 선기록 → `harness-stamp mark` → `npm test` 전건.
⚠ 대상이 없으면 하지 않는다. **먼저 세어서 보고**할 것(로컬 실측 기준 0건이었으나 실서버는 다를 수 있다).

## 5. 회귀 박제
신규 `test/board-gallery-link.test.js`
- **INV-BG1**: 게시판 설정이 **꺼져 있으면** 갤러리 글을 써도 `student_gallery` 행이 **생기지 않는다** ← 현재는 끌 수 없음

- **INV-BG5**: 대표 `image_url` == 첫 이미지 attachment
- **INV-BG6 (과잉 차단 방지)**: 파일 선택으로 올린 기존 방식이 **여전히 동작**한다
