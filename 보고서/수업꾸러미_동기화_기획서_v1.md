# 수업꾸러미 동기화(교사 주도 lockstep) 모드 — 정식 기획서 v1

작성: UI 디자이너 + 실시간 협업 아키텍트(겸임)
대상 파일(실동작): `public/class/lesson-player.html` (3535줄), `socket/index.js`, `routes/lesson.js`, `db/class.js`, `server.js`
산출물 성격: **기획서(Markdown)만. 코드 수정 금지.** 모든 설계는 아래 "코드 근거" 절의 실측 라인을 근거로 한다.

## 0. 한 줄 요약

교사가 수업꾸러미(=lesson, 콘텐츠 여러 개 묶음) 플레이어 헤더의 **"동기화 시작" 토글**을 켜면, 같은 수업을 열람 중인 학생(일반 멤버)은 교사가 보는 콘텐츠로 **강제 이동·잠금(lockstep)** 되고, 교사가 콘텐츠를 바꾸면 학생도 따라간다. 교사가 토글을 끄면 학생은 다시 자유 이동한다. **CBT 감독 패턴(`socket/index.js`)을 그대로 차용**하여 신규 룸 `lesson:{id}`와 5개 이벤트로 구현한다.

## 2. 동기화 상태 모델 (서버 보관)

### 2.1 메모리맵 정의 (`socket/index.js` 모듈 레벨, `activeExams`와 동일 패턴)

```js
// 런타임 전용: 수업꾸러미 동기화 상태
// Key: lessonId(String), Value: 아래 구조
const lessonSync = new Map();
// lessonSync.get(lessonId) = {
//   on:            false,          // 동기화 ON/OFF
//   controllerId:  null,           // 현재 제어 교사 userId
//   controllerName:'',             // 표시용 이름 (display_name||username)
//   classId:       null,           // 멤버십 검증·로깅용
//   currentIndex:  0,              // 교사가 보는 콘텐츠 인덱스 (학생 강제 이동 목표)
//   members:       new Map(),      // userId -> {socketId, role, displayName} (현재 룸 접속자)
//   updatedAt:     0               // Date.now() — 최신성/디버깅
// }
```

### 2.2 DB 영속 필요 여부 — **불요 (메모리만)**. 근거:

1. **세션성 기능**: lockstep은 "지금 같이 보는" 실시간 동기화다. 교사가 떠나면 의미가 사라진다(엣지케이스 §4 자동 해제 참조). 서버 재시작 후 과거 동기화 상태를 복원할 가치가 없다.
2. **재접속/새로고침 복원은 join push로 충분**: 학생 새로고침/늦은 입장 시 `lesson:join`에서 **서버가 현재 메모리 상태를 그 소켓에 즉시 push**(§3.2)하여 복원한다 → DB 없이 복구 완결.
3. **서버 재시작 시**: 메모리 소실 = 모든 소켓도 disconnect되어 클라가 자동 재연결 후 `lesson:join` 재전송 → 상태가 비어 있으면 "동기화 꺼짐(자유)"으로 안전 수렴(fail-open). 학생이 영구히 갇히는 사고 없음.
4. **부작용 없음**: `activeExams`(L7)도 동일하게 메모리 전용 + 주기적 정리(L441~455)로 운영 중. 같은 운영 모델을 재사용한다.

> 예외(향후 확장): "교사 화면 따라가기 로그(누가 언제 동기화)"를 LRS에 남기고 싶다면 `xapiSpool`(routes/lesson.js L11 이미 import) 또는 learning-log로 **이벤트만** 적재. 상태 자체의 영속은 여전히 불요. **v1 범위 외.**

### 2.3 정리(GC)
- `disconnect`에서 컨트롤러가 나가면 즉시 `on=false` + 학생 통지 후, 룸에 아무도 없으면 `lessonSync.delete(lessonId)` (§4.2).
- 보강: `activeExams`와 동일하게 1시간 주기 sweep에서 `members.size===0`인 엔트리 제거(L441~455 패턴 차용).

## 3. Socket 이벤트 계약 (이름·payload·방향·권한)

룸 네이밍: **`lesson:{lessonId}`** (CBT의 `exam:{id}` 패턴과 동형). 컨트롤러 식별을 위한 별도 supervisor 룸은 **불필요** — 컨트롤 권한은 emit마다 서버가 재검증한다.

### 3.1 클라이언트 → 서버

| 이벤트 | payload | 보내는 주체 | 서버 처리 |
|--------|---------|------------|-----------|
| `lesson:join` | `{ classId, lessonId }` | 학생·교사 **공통** | ① `class_members(active)` 또는 admin 검증(미통과 시 무시·`lesson:error` emit) → ② `socket.join('lesson:'+lessonId)` → ③ `lessonSync` members에 등록 → ④ **즉시 현재 상태를 이 소켓에만 emit** `lesson:sync:state`(아래) → 늦은 입장/새로고침 복원 |
| `lesson:sync:start` | `{ classId, lessonId, index }` | **교사 전용** | 권한 재검증(§5). 통과 시 `on=true, controllerId=userId, controllerName, currentIndex=index, updatedAt=now` → **룸 전체 브로드캐스트** `lesson:sync:state{on:true,...}` |
| `lesson:sync:move` | `{ classId, lessonId, index }` | **교사 전용(=controllerId 본인)** | 권한+컨트롤러 일치 검증. throttle 1초(§3.4) 통과 시 `currentIndex=index, updatedAt=now` → 룸 브로드캐스트 `lesson:sync:state{on:true,index}` |
| `lesson:sync:end` | `{ classId, lessonId }` | **교사 전용** | 권한 재검증. `on=false` (controllerId/index는 유지해도 무방) → 룸 브로드캐스트 `lesson:sync:state{on:false}` |

> 학생(member)이 `start/move/end`를 emit해도 §5 권한검증에서 **즉시 무시 + 선택적 `lesson:error{message}` 1회 통지**(연타 방지 throttle). 클라의 `isTeacher` 절대 신뢰 금지.

### 3.2 서버 → 클라이언트

| 이벤트 | payload | 방향 | 용도 |
|--------|---------|------|------|
| `lesson:sync:state` | `{ on, index, controllerName }` | 룸 전체 또는 특정 소켓 | **단일 상태 채널**. 학생 클라는 이 이벤트만 듣고 (a) `on=true`면 `index`로 강제 이동 + 잠금 UI, (b) `on=false`면 잠금 해제. 교사 클라는 본인이 켠 상태 확인용(중복 갱신 무해). join 직후 1회(복원) + 상태 변경마다 브로드캐스트 |
| `lesson:sync:peers` (선택) | `{ count }` | 컨트롤러 소켓에만 | 교사 헤더 "N명 동기화 중" 표기용. join/leave/disconnect 시 갱신 |
| `lesson:error` | `{ message }` | 위반 소켓에만 | 멤버 아님/권한 없음 등 사유 통지 (학생 우회 emit 차단 피드백) |

> **상태 채널 단일화 원칙**: 학생은 `lesson:sync:state` **하나만** 구독하면 시작/이동/종료/복원 모든 시나리오가 커버된다. 별도 start/move/end 수신 이벤트를 만들지 않는다(상태 불일치 위험 제거).

### 3.3 학생 클라 수신 처리 (의사코드 — `selectContent`가 갈고리)

```js
socket.on('lesson:sync:state', ({ on, index, controllerName }) => {
  syncState = { on, index, controllerName };
  if (on) {
    if (currentIndex !== index) {
      selectContent(index);                 // ← 핵심 갈고리: 강제 이동 (L1098)
      showToast('선생님 화면으로 이동했어요');  // 짧은 토스트 (L2143)
    }
    applyLockUI(true, controllerName);       // 잠금 배너 + prev/next/목차 비활성
  } else {
    applyLockUI(false);                      // 잠금 해제 + 컨트롤 복구
  }
});
```

### 3.4 throttle 필요 여부 — **`lesson:sync:move`에 1초 1회 적용**
- 근거: 교사가 이전/다음을 연타하거나 목차를 빠르게 훑으면 브로드캐스트 폭주 + 학생 화면 깜빡임. CBT의 throttle 패턴(L17~18, L260~264)을 `key = ${userId}_${lessonId}`로 재사용.
- 단, **마지막 이동은 반드시 반영**: throttle로 버린 move가 마지막이면 학생이 잘못된 위치에 멈춘다 → "trailing flush"로 1초 뒤 최신 `currentIndex`를 한 번 더 브로드캐스트(leading+trailing). `start`/`end`는 throttle 제외(즉시 반영).

## 4. 엣지케이스 처리 규칙 (각 동작 명시)

### 4.1 늦게 입장한 학생 / 학생 새로고침
- 클라는 로드 직후(학생 플레이 모드일 때) `lesson:join` emit → 서버가 **그 소켓에만** 현재 `lesson:sync:state` push.
- `on=true`면 즉시 `selectContent(currentIndex)`로 점프 + 잠금. `on=false`면 그대로 자유.
- 구현 주의: `lesson:join`은 **`loadPlayer()`에서 `contents` 로드가 끝난 뒤**(selectContent 가능 상태) emit. 상태가 먼저 와도 `contents` 미로드면 `pendingSyncState`에 보관했다가 로드 완료 후 적용.

### 4.2 교사가 플레이어를 닫거나 연결 끊김 → **자동 해제(fail-open)**
- **정책: 컨트롤러 소켓 disconnect 시 즉시 동기화 종료.** 학생이 영구히 갇히는 사고를 원천 차단.
- 처리: `disconnect` 핸들러(L406 확장)에서 `socket.userId === lessonSync.controllerId`이면 → `on=false` → 룸에 `lesson:sync:state{on:false}` 브로드캐스트(학생 잠금 해제) + 학생에게 `classToast('선생님이 나가 자유 이동으로 전환됐어요','info')`.
- **grace 시간 — v1은 0초(즉시 해제) 채택.** 근거: 교사가 "돌아가기/나가기"(L616·627·2141)로 의도적으로 나가는 경우가 다수이고, 잠긴 학생을 빨리 풀어주는 안전이 우선. (재연결 깜빡임 흡수용 3~5초 grace는 P1 옵션으로 명시만.)
- 교사가 단지 다른 탭으로 갔다가 돌아오는 경우는 disconnect가 아니므로 동기화 유지(소켓 연결 살아있음).

### 4.3 co_teacher/공동교사 2명 → 컨트롤 주체 규칙
- **"토글한 사람이 controller"** (last-writer-wins). 컨트롤러가 정해진 상태에서 다른 교사가 `lesson:sync:start`를 보내면 → **제어권 이양**: `controllerId`를 새 교사로 교체 + 룸에 `controllerName` 갱신 브로드캐스트.
- `lesson:sync:move`는 **현재 controllerId 본인만** 허용(다른 교사 move는 무시). 이양받으려면 먼저 start로 잡는다.
- 교사 UI 안내: 다른 교사가 이미 켠 상태면 토글 라벨을 "동기화 이어받기"로 표기(중복 컨트롤 충돌 예방, §5 UX).
- v1 권한: `owner` + `co_teacher` + `admin` 모두 컨트롤 가능. (제한이 필요하면 owner만으로 좁히는 옵션 명시.)

### 4.4 교사 본인은 **절대 잠기지 않음**
- 교사 클라는 `lesson:sync:state`를 받아도 **잠금 UI/강제 이동을 적용하지 않는다**(상태 표시만). 분기 기준: FE `isOwner`(L1211 동일식 `currentUser.id === lessonData.teacher_id`) **또는** co_teacher(아래) → `isTeacherViewer=true`면 lock 미적용.
  - co_teacher는 `lessonData.teacher_id`와 다르므로 FE에서 별도 신호 필요 → `/api/lesson/:classId/:lessonId` 응답에 이미 없는 `myRole`을 **서버 push로 보강**: `lesson:join` 응답(또는 `lesson:sync:state`)에 `youAreController`/`canControl` 불리언을 실어 FE가 교사뷰 여부를 신뢰 가능하게 한다(클라 자가판단 금지).
- **미리보기(`isPreviewMode`)/생성(`isCreatorMode`)/편집(`isEditMode`) 모드에서는 동기화 전 기능 비활성**: 토글 버튼 미표시 + `lesson:join` 미전송. (이 모드들은 학생 플레이가 아님 — L829~833 플래그로 분기, 셀프체크가 동일하게 막히는 L1640과 일관.)

### 4.5 학생이 동기화 중 수동으로 콘텐츠 클릭/이동 시 → **차단(즉시 되돌림)**
- 1차 방어(UI): 잠금 중 `#prevBtn`/`#nextBtn` `disabled`, `.step-item`에 `pointer-events:none` + `aria-disabled="true"` → 물리적으로 못 누름.
- 2차 방어(로직): 그래도 `selectContent`가 호출되면(키보드/직접 호출 등) **가드 진입**: `if (syncState.on && !isTeacherViewer && index !== syncState.index) { selectContent(syncState.index); showToast('지금은 선생님 화면을 따라가는 중이에요'); return; }`. 즉 잠금 중 학생의 목표 외 이동은 **교사 위치로 즉시 되돌림**.
- 가드는 `selectContent` **최상단 1곳**에만 넣어 모든 진입점(목차·prev/next·navigate)을 일괄 차단(단일 갈고리 L1098 활용).

### 4.6 기타
- **콘텐츠 개수 0 / 로드 실패**: 동기화 토글 비활성(켤 대상 없음), 학생 잠금 미적용. 빈 상태 안내(기존 L1038 빈 목차 메시지 유지).
- **index 범위 밖**(교사·학생 contents 길이 불일치 가능성): 학생 클라에서 `index`를 `0..contents.length-1`로 clamp 후 적용. 불일치 시 콘솔 경고만, 깨짐 없이.
- **동일 교사 다중 탭**: controllerId는 userId 단위 → 같은 교사의 어느 탭에서든 move 허용(소켓ID 아님, userId 기준).

## 5. 권한·보안 (서버측 재검증 필수)

- **모든 교사 제어 이벤트(`start/move/end`)는 서버에서 매번 재검증**. 클라가 보낸 `isTeacher`/role 신뢰 금지. 검증 함수(의사코드, `socket/index.js`의 supervisor:join L110~137 패턴 차용):

```js
function canControlLesson(userId, classId, lessonId) {
  // 1) 클래스 active 멤버 + 역할 확인
  const m = db.prepare("SELECT role FROM class_members WHERE class_id=? AND user_id=? AND status='active'").get(classId, userId);
  const role = m ? m.role : null;
  if (role === 'owner' || role === 'co_teacher') {
    // 2) lesson이 실제 그 classId 소속인지 교차검증 (exam의 class_id 검증 L122~126과 동형)
    const lesson = lessonDb.getLessonById(lessonId);
    if (lesson && String(lesson.class_id) === String(classId)) return true;
  }
  // 3) admin 운영 허용
  const u = db.prepare('SELECT role FROM users WHERE id=?').get(userId);
  if (u && u.role === 'admin') return true;
  return false;
}
```

- **멤버 아닌 자 룸 차단**: `lesson:join`에서 `class_members(active)` 미통과 시 join 거부 + `lesson:error` (잠입 방지 — `join:class` L33~43와 동일 원칙).
- **lesson↔class 교차검증**: 컨트롤·join 모두 `lesson.class_id === classId` 확인(타 클래스 lessonId 끼워넣기 차단).
- **emit 스푸핑 무력화**: 학생이 `lesson:sync:state`를 emit해도 서버가 그 이벤트를 듣지 않으므로(서버→클라 단방향) 무효. 학생→서버 채널은 `lesson:join`만 의미 있음.

### 6.4 사용자 중심 5대 기준 자가점검
- (a) 진입경로: 교사는 헤더 우측 토글 1개로 시작/종료 — 한눈에 보임.

- (c) 복귀 동선: 교사 토글 OFF 즉시 학생 자유 / 학생은 별도 조작 불필요(자동 복구).
- (d) 빈·오류: 콘텐츠 0=토글 비활성 안내, 교사 이탈=자동 해제 토스트.
- (e) 라벨: "동기화 시작/동기화 중/이어받기", "선생님 화면을 따라가고 있어요" — 초등학생도 이해.
