### ⚠ 웨이브 1에서 드러난 함정 — 반드시 인지
1. **`server.js` 기동이 `data/sessions.db` 를 무조건 삭제한다.** 포트를 나눠도 다른 팀·PM 세션이 끊긴다. **서버 기동은 꼭 필요할 때 1회만.**
2. **`DB_PATH` 격리가 완전하지 않다.** `routes/content.js:806`·`routes/self-learn.js`(33·49·220·265·545·1453행)가 `data/dacheum.db` 를 **cwd 상대경로로 하드코딩**한다. **팀 4는 스스로채움이 주 범위이므로 이 결함에 정면으로 노출된다** — 프로세스 cwd 를 임시 디렉터리로 옮기고 그 안에 `data/dacheum.db` 사본을 두어 두 경로가 같은 파일을 가리키게 할 것. 정본 오염 시 즉시 중단하고 PM 에 보고.
3. **전 서비스 시각이 UTC 로 표시되어 9시간 어긋난다**(`W1-T2-10`). 시각 관련 판정 시 이 사실을 전제로 볼 것 — 새로 발견한 것처럼 보고하지 말고 "동일 결함"으로 참조.

### 2계정 동시 시나리오 (팀 5 필수)
```js
const b = await chromium.launch();
const teacher = await b.newContext({ viewport:{width:1440,height:900} });
const student = await b.newContext({ viewport:{width:1440,height:900} });
// 각 컨텍스트에서 개별 로그인 → 쿠키 분리 → 한쪽 동작이 다른 쪽에 즉시 반영되는지 확인
```
- 실시간 이벤트는 **폴링이 아니라 소켓**이다. `page.waitForFunction()` 으로 DOM 변화를 기다리되, 타임아웃을 넉넉히(10s) 두고 **미반영이면 그 자체가 결함**으로 기록한다.
- 소켓 미수신과 화면 미갱신을 구분하려면 `read_console_messages` 또는 `page.on('console')` 로 이벤트 수신 로그를 함께 본다.

# 팀 5 — 실시간 · 출결 · 감정 · 게이미피케이션

**가장 어려운 팀이다.** 2계정 동시 접속이 필수이고, 소켓 이벤트는 화면에 흔적을 안 남기고 사라질 수 있다.

## T5-1. 🔴 CBT 이탈 감지 (RFP 필수 기능)

**절차**
1. teacher1 → 평가 생성 → `/cbt/supervisor.html` 감독 화면 열기
2. student1 → `/cbt/player.html` 응시 시작
3. 학생 컨텍스트에서 **탭 이탈 유발** — `page.evaluate(() => document.dispatchEvent(new Event('visibilitychange')))` 또는 새 탭 열기/포커스 이동. **실제 이벤트 경로를 코드로 확인해 정확히 유발할 것**
4. 몇 초 뒤 복귀
5. 이를 **3회 반복**하고 각 이탈의 지속시간을 다르게 할 것

**확인**
- **교사 감독 화면에 실시간으로** 이탈 횟수·이탈 시간이 뜨는지 (새로고침 없이)
- Socket.IO 이벤트: `tab:leave` / `tab:return` / `focus:lost` / `focus:gained`
- **서버 Throttle**(학생당 1초 1회)이 실제로 동작하는지 — 짧은 간격으로 여러 번 유발해 확인
- **누적 시간**이 맞는지 — `focus:lost{duration:0}` 고정이 아니라 실제 경과초를 보내는지(과거 결함 이력 있음)
- 제출 후에도 기록이 남는지
**DB**: `exam_students`(`tab_switch_count`, `total_leave_time`)
**실패로 볼 것**: 교사 화면 미갱신 · 횟수만 늘고 시간은 0 · 새로고침해야 보임 · Throttle 없이 폭주

## T5-2. 🔴 수업꾸러미 동기화 (교사 lockstep)

**절차**
1. teacher1 → `/class/lesson-player.html` 진입 → **동기화 ON**
2. student1(일반 멤버) → 같은 수업 진입 → **교사 위치로 강제 이동 + 조작 잠금**되는지
3. 교사가 다른 콘텐츠로 이동 → 학생도 따라오는지
4. **동기화 OFF** → 학생이 자유롭게 이동 가능한지
5. 교사가 페이지를 이탈(닫기) → 잠금이 풀리는지

**확인**
- `socket/index.js` 의 `lessonSync` 메모리맵과 `lesson:sync:*` 이벤트
- **교사 자신은 잠기지 않아야 한다** — 과거 결함: broadcast 에 `youAreController` 를 실으면 교사 echo 가 자기 값을 덮어써 교사도 잠김. 지금은 `controllerId` 를 동봉해 FE 가 파생하는 구조
- 권한: **owner + admin 만** 컨트롤러가 될 수 있음(co_teacher 는 휴면)
- 서버 재기동 시 메모리맵이 날아가는데 그때 학생이 영구 잠금되지 않는지
**실패로 볼 것**: ON 해도 학생이 안 따라옴 · OFF 해도 잠금 유지 · 교사 자신이 잠김 · 이탈 후 학생 영구 잠금

- **`/class/manage.html?id=1` 에 멤버 학생이 진입 가능**한 문제(웨이브 1 접수) 재확인
**실패로 볼 것**: 코드 없이 가입 가능 · 강퇴 후에도 접근 · 학생이 관리 화면 진입

## T6-3. 명예의 전당

**절차** 포털 메인의 클래스/크리에이터 명예의 전당
**확인**: **랭킹 산정 근거를 코드로 확인**하고 화면 값과 대조 · 데모/탈퇴 계정 혼입 여부 · 빈 상태 안내
**실패로 볼 것**: 근거 불명 숫자 · 탈퇴 계정 등재

## T6-4. 포털 메인

**절차** 비로그인 / 학생 / 교사 각각으로 `/` 진입
**DB**: `featured_sections` · `featured_section_items`
**확인**
- **비로그인에게 무엇이 보이는가** — 인기 콘텐츠·명예의 전당은 공개, 개인 데이터는 비공개여야 함
- 인기 콘텐츠 선정 기준 · 썸네일 로딩(웨이브 1에서 플레이스홀더 404 5종 발견)
- **가로 스크롤 0**(과거 모바일 가로 스크롤 결함 이력)
**실패로 볼 것**: 비로그인에게 개인 데이터 노출 · 인기 콘텐츠에 미승인·비공개 혼입
