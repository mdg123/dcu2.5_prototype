> 작성: 도메인 전문가(LRS·학습분석·교육 거버넌스) · 2026-07-08
> 성격: **읽기 전용 검토 + 콘텐츠 스펙**(코드 수정 없음). 개발 착수 전 UI 디자이너·Backend가 참조할 기획 근거.
> 대상: 충북교육청 관리자 LRS `public/lrs/index.html`(관리자 4탭 9뷰) + `routes/lrs.js` API.

## 0. 핵심 요약 (Executive Summary)

- **문제의식**: 현재 관리자 LRS의 9개 뷰는 대부분 "화면에서 보고 끝나는 분석"이다. 특히 **'리포트' 탭이 실제로는 '내보내기(raw CSV/xlsx)' 하나뿐**이라, 교육청이 정작 원하는 *"한 장으로 읽는 정책 브리프"*가 없다. 원자료 반출은 리포트가 아니라 리포트의 **부속 액션**이다.
- **가장 큰 기회**: 격차·취약 성취기준·서비스 활용·데이터 신뢰도 같은 정책 판단 재료는 **이미 API에 다 있다**(equity·service-ops·weak-trend·dataset-coverage·admin-kpi). 신규 원자료 수집 없이 **기존 6개 엔드포인트를 조립**하면 요약 보고서가 즉시 성립한다.
- **정체성 정리**: '운영' 탭(데이터품질+교사실행지수+표준체계)은 성격상 **"수집·표준 건전성 = 데이터 신뢰성"**이다. 반면 지금 '현황 분석'에 있는 **'서비스 운영 진단'(사장/과열 판단)은 정책·활용 의사결정**이라 이름이 서로 어긋난다. → **'운영' → '데이터 신뢰성'으로 개명**하고, '서비스 운영 진단'은 이름을 '서비스 활용 진단'으로 다듬어 현 위치(현황 분석) 유지 권고.

### 콘솔 3줄 요약
```
1. '리포트'=내보내기(raw)뿐 → 진짜 요약 보고서로 승격. 신규 데이터 0, 기존 6개 API(admin-kpi·service-ops·equity·weak-trend·dataset-coverage·cross) 조립만으로 8블록 정책 브리프 조립 가능. 내보내기는 그 하위 액션으로 흡수.
2. '운영' 탭 정체성 혼선: 데이터품질+교사실행+표준체계="데이터 신뢰성"인데 '서비스 운영 진단'은 현황분석에 있음 → '운영'을 '데이터 신뢰성'으로 개명 권고. 메뉴명 '내보내기'→'요약 보고서', '표준체계 분석'→'수집 표준 점검' 등 6건 재검토.
3. 빈약 뷰(교사 실행지수) = 시드 부족+산식 캡(100) 탓. a-xapi(표본<200 자동숨김)와 동일하게 '표본 게이트'로 통일 — 교사 표본/활동 임계 미달 시 자동 숨김+빈상태 안내, 데이터 쌓이면 자동 부활.
```

## 1. 현재 관리자 IA 실측 (4탭 · 9뷰)

FE는 `group` 필드를 무시하고 **category 기준 인페이지 가로 탭**으로 평탄화 렌더한다(`renderInPageTabs`). 실제 사용자가 보는 상단 탭 라벨은 `MENU_CATEGORY_LABEL`(index.html:1356) 기준이다.

| 상단 탭(category) | 뷰 id | 라벨(현재) | 주 데이터 소스 API |
|---|---|---|---|
| **홈** (`home`) | `a-home` | 한눈 현황 | `/stats/admin-kpi` |
| **현황 분석** (`analytics`) | `a-svc-ops` | 서비스 운영 진단 | `/stats/service-ops` |
| | `a-macro` | 지역별 성취수준 비교 | `/stats/equity` (+`/stats/macro-drill`) |
| | `a-cross` | 활동×성취 교차 | `/stats/cross-activity-achievement` |
| | `a-time` | 학습시간 분석 | `/stats/time-by-unit` |
| **운영** (`operations`) | `a-quality` | 데이터 품질 | `/dataset-coverage` (+by-service·by-achievement) |
| | `a-teacher-idx` | 교사 실행지수 | `/stats/teacher-index-dist` |
| | `a-xapi` | 표준체계 분석 | `/xapi/overview` 등 (**표본<200 자동숨김**) |
| **리포트** (`reports`) | `a-export` | 내보내기 | `/export` (+dataset-coverage·stats/daily) |

> 참고: `a-macro`는 구(舊) '형평성' 뷰와 '거시 5단 드릴'을 통합한 것으로, `/stats/equity`가 units·metrics·trend·priorityUnits·crossLevelRegion을 한 번에 반환한다(이미 매우 풍부).

## 2. 탭·뷰별 정책 인사이트 가치 정의표 (검토 과제 1)

각 뷰가 **교육청 관리자에게 어떤 질문에 답하고, 어떤 의사결정을 유도하는가**, 그리고 **현재 그 가치를 실제로 주는가**를 판정한다.

### 홈 — `a-home` 한눈 현황
- **답하는 질문**: "플랫폼이 살아있나? 오늘/이번 주 얼마나 쓰이나? 어느 학교급이 활발한가?"
- **의사결정**: 전사 활성 모니터링(정례 보고 첫 장), 학교급 편중 인지 → 저활성 급 대상 캠페인/독려.
- **가치 판정**: **충족**. 최근 정합·정직화(학습활동 7종·학생 스코프·시드 비중 각주)로 신뢰성이 크게 개선됨. KPI 8종 + 8주 추이(급별 멀티라인) + 학교급 미니카드는 국가 대시보드의 "landing overview" 관행에 부합.
- **개선 여지**: '오늘 활동 스냅샷'은 홈 KPI와 중복. 여유가 되면 "이번 주 vs 직전주 Δ", "전년 동월 대비"(데이터 축적 후) 한 줄만 추가하면 브리핑 가치↑.

### 현황 분석 — `a-svc-ops` 서비스 운영 진단
- **답하는 질문**: "7개 서비스 중 어디가 사장(死藏)되고 어디가 과열인가? 최근 급감한 서비스는?"
- **의사결정**: **예산·홍보·연수 재배분**(저활용 서비스 폐지/개선/집중 프로모션), 장애 조기 포착(급감 = 로거 장애 후보).
- **가치 판정**: **충족(설계 우수)**. share·추세Δ·재방문율·1인당 시간·룰베이스 진단(정상/저활용/급감)에 더해 **시드 과경보 게이트(MIN_ABS=30, seedInfluenced 톤다운)**까지 갖춰 "빨강 남발"을 억제 — 이는 실제 학습분석 대시보드에서 가장 흔히 실패하는 지점을 선제적으로 막은 것.
- **주의**: 이름이 '운영 진단'이라 '운영' 탭과 개념 충돌(§3에서 개명 권고).

### 현황 분석 — `a-macro` 지역별 성취수준 비교
- **답하는 질문**: "어느 지역·학교급에 성취 격차가 크고, 어디가 이중취약(활용도 낮고 성취도 낮음)인가?"
- **의사결정**: **예산·연수·보충 프로그램의 우선 투입지 선정**. 이것이 교육청 LRS의 *핵심 정책 산출물*.
- **가치 판정**: **충족(가장 정책성 높은 뷰)**. `/stats/equity`가 (1) 격차 지표 4종(gap·IQR·**CV**·하위20%비), (2) 사분면(활용×성취 → both_low 이중취약), (3) 3구간 추세, (4) **우선개입 후보(priorityUnits)**, (5) **학교급×지역 교차(crossLevelRegion, top/bottom·격차pp)**를 반환. n<10 마스킹으로 개인정보·소표본 왜곡도 차단. 국가수준 학업성취도 평가(성취수준 격차 리포트) 관행에 가장 근접.
- **개선 여지**: 여기서 나오는 top gap·우선개입 단위가 **요약 보고서의 핵심 블록**이 되어야 함(§4-블록3).

### 현황 분석 — `a-cross` 활동×성취 교차
- **답하는 질문**: "'많이 하면 잘하는가?' 활용량과 성취가 실제로 연관되나? 콘텐츠·자기주도 학습이 성취에 기여하나?"
- **의사결정**: **활용 독려의 정당화 근거**(활동↑→성취↑ 확인 시 "쓰게 하자"가 정책적으로 정당), 특정 서비스의 성취 기여 입증.
- **가치 판정**: **부분 충족**. 산점도+3분위 매트릭스+상/하위 집단 격차(contentCompare·selfLearnCompare)는 인과가 아닌 상관이지만 정책 커뮤니케이션엔 유용. 단 `smallSample:true(n<30)` 구간에선 해석 주의 배너 필수. 시드 의존도가 높을수록 착시 위험 → realOnly 토글과 병행 안내.
- **성격**: 이 뷰는 "탐색/연구"에 가깝고 "정례 보고" 재료는 아님. 리포트에는 **한 줄 결론(활동상위-하위 성취 격차 Npp)**만 인용하면 충분.

### 현황 분석 — `a-time` 학습시간 분석
- **답하는 질문**: "단위별 1인당 학습시간은? 언제(요일·시간대) 몰리나?"
- **의사결정**: 서버 증설/점검 시간대, 방과후·야간 학습 실태 파악, 학습시간 격차 인지.
- **가치 판정**: **부분 충족(운영 보조)**. 요일×시간 히트맵은 인프라 운영엔 유용하나 *정책* 의사결정 직접성은 낮음. 학습시간 결측률(dataset-coverage)과 함께 읽어야 신뢰 가능. "시간=성실도"로 오독되지 않게 라벨 주의.

### 운영 — `a-quality` 데이터 품질
- **답하는 질문**: **"이 대시보드의 숫자를 믿어도 되나?"** (성취/교과/시간 결측률, 세션 커버리지, 최근 동기화 시각).
- **의사결정**: **모든 상위 판단의 전제**. 결측률↑이면 격차·성취 지표를 신뢰하지 말아야 함 → 서비스 로거 풍부화 요청, 집계 재빌드.
- **가치 판정**: **충족(거버넌스 핵심)**. "정당 분모"(결측이 의미있는 activity_type만 분모) 방식 + 세션 커버리지(양의 지표) + 서비스별 결측 + last_synced는 데이터 거버넌스 모범. 이 뷰는 **요약 보고서에 '신뢰도 배지'로 반드시 상단 노출**되어야 함(§4-블록6).

### 운영 — `a-teacher-idx` 교사 실행지수
- **답하는 질문**: "교사들이 플랫폼을 얼마나 실질적으로 운영(반 개설·콘텐츠 제작·평가 출제·피드백)하나? 학교급·지역별 실행 편차는?"
- **의사결정**: **교사 연수·인센티브 대상 선정**, 저실행 학교 지원.
- **가치 판정**: **미흡(현재 데이터 빈약)**. 이유: (1) 산식이 raw count 가중합을 `Math.min(100, raw)`로 **100에서 절단** → 상위가 뭉개짐, (2) 학교급 판정이 `school_name LIKE '%초등%'` **문자열 휴리스틱**이라 미분류 다수, (3) 무엇보다 **시드에 교사 활동 로그가 희박**해 분포가 평평. → 데이터가 쌓이면(실교사 트래픽) 분포가 살아나는 구조는 맞으나, **지금 화면에 내놓으면 "빈 껍데기"로 신뢰를 깎음**. §5에서 표본 게이트 처리 권고.

### 운영 — `a-xapi` 표준체계 분석
- **답하는 질문**: "우리 로그가 xAPI/AIDT 표준 체계(교과·학년·성취기준 노드)에 정합하게 매핑되나? 표준 문장이 얼마나 쌓였나?"
- **의사결정**: **AIDT/디지털교과서 연계 준비도 점검**, 대외 표준 리포팅 가능 여부 판단.
- **가치 판정**: **부분(구조는 옳음, 표본 부족)**. `state._xapiSampleCount < 200`이면 **탭 자체를 자동 숨김**하고 랜딩을 '데이터 품질'로 되돌리는 게이트가 이미 있음 — 올바른 설계. 표본이 차면 자동 부활. **처리 방침은 이대로 유지(모범)**, 나머지 빈약 뷰도 이 패턴으로 통일(§5).

### 리포트 — `a-export` 내보내기
- **답하는 질문**: (없음) "원자료를 파일로 뽑고 싶다."
- **의사결정**: 외부 분석·감사·타 부서 제출용 데이터 반출.
- **가치 판정**: **미흡(정체성 오류)**. 필터 요약 KPI 4장은 있으나 **화면 인사이트가 사실상 0**, 본질은 CSV/xlsx 다운로드. "리포트"라는 이름과 실제 기능(내보내기)의 **불일치**가 이번 검토의 핵심 시정 대상. → §4에서 요약 보고서로 승격.

## 3. '운영' 탭 정체성 재편 권고 (검토 과제 2)

### 3-1. 진단: 개념 축이 어긋나 있다
현재 배치를 성격축으로 다시 그리면:

| 뷰 | 실제 성격 | 지금 위치 | 어긋남 |
|---|---|---|---|
| a-svc-ops 서비스 운영 진단 | **서비스 활용·정책**(사장/과열/급감 → 예산·홍보 판단) | 현황 분석 | 이름이 '운영'인데 '운영' 탭엔 없음 |
| a-quality 데이터 품질 | **데이터 신뢰성**(결측·세션·동기화) | 운영 | ○ |
| a-teacher-idx 교사 실행지수 | **참여 건전성**(교사 로깅·실행) | 운영 | △ (신뢰성보다 '참여'에 가까움) |
| a-xapi 표준체계 분석 | **수집 표준 정합성**(xAPI/AIDT 매핑) | 운영 | ○ |

즉 '운영' 탭의 실제 공통분모는 **"데이터가 제대로·표준대로 수집되고 있는가 = 데이터 신뢰성/거버넌스"**다. 그런데 '서비스 운영 진단'이라는 *활용·정책* 뷰가 다른 탭(현황 분석)에 있어, **'운영'이라는 단어가 두 곳에서 다른 뜻으로 쓰인다.**

### 3-2. 권고 (2안 중 A안 채택 권장)

**A안(권장) — 이름을 성격에 맞춘다. 이동 없음(리스크 최소).**
- **'운영' → '데이터 신뢰성'**(또는 '데이터 거버넌스')로 상단 탭 라벨 개명. 하위 3뷰(품질·교사실행·표준)가 모두 "수집 건전성"으로 자연스럽게 묶임.
- **'서비스 운영 진단' → '서비스 활용 진단'**으로 개명하고 **'현황 분석' 유지**. ('운영'이라는 단어를 데이터-거버넌스 쪽에만 남겨 중복 제거.)
- 결과 IA:
  - **홈**: 한눈 현황
  - **현황 분석**(무엇이 일어나나): 서비스 활용 진단 · 지역별 성취수준 비교 · 활동×성취 교차 · 학습시간 분석
  - **데이터 신뢰성**(믿어도 되나): 데이터 품질 · 교사 실행지수 · 수집 표준 점검
  - **리포트**: 요약 보고서(+내보내기)

**B안(대안) — 서비스 운영 진단을 '운영'으로 이동.**
- '운영'을 활용+신뢰 혼합 탭으로 둠. 그러나 이러면 "성취 격차(현황)"와 "서비스 활용(운영)"이 갈라져, 정작 함께 봐야 할 *활용↔성취* 판단이 두 탭으로 분리됨. → **비권장.**

> 근거: KERIS/AIDT 계열 관리자 대시보드와 1EdTech(구 IMS) Caliper/xAPI 거버넌스 관행은 **"활용·성과(analytics)"와 "데이터 품질·표준 정합(data governance)"을 별 축으로 분리**한다. A안이 이 관행에 부합한다.

## 4. ★ '리포트' = 요약 보고서 콘텐츠 스펙 (검토 과제 3, 핵심 산출물)

### 4-1. 원칙
1. **한 화면(스크롤 1~2회) / 인쇄·PDF 1~2장에 정책 핵심을 요약**한 브리프. 표·차트는 "결정을 돕는 최소"만.
2. **신규 원자료·외부연동 0.** 아래 8블록은 전부 **기존 API 재조립**으로 성립(§4-3 매핑).
3. **상단에 스코프·신뢰도·생성시각을 못박아** 보고서로서의 맥락(기간, 실데이터/예시 포함, 결측)이 항상 따라붙게.
4. **내보내기(raw)는 리포트의 최하단 '부속 액션'으로 흡수** — "이 보고서의 근거 데이터를 CSV/xlsx로" 형태.
5. 각 블록 하단에 **규칙 기반 권고 문장 1줄**(자동 생성). AI 판단이 아니라 임계 규칙 → 정직·재현 가능.

### 4-2. 보고서 구성 (블록 순서 = 위→아래)

**[헤더] 보고서 표지 밴드**
- 제목 "다채움 학습데이터 정책 요약 보고서", **대상 기간**(period 라벨), **스코프**(전체/실데이터만 토글 상태), **생성 시각**, **데이터 기준일**(dataset-coverage.last_synced).
- 예시 포함 여부 배지: realOnly=false면 "예시 데이터 포함(약 N%)" 경고 칩(admin-kpi.learnHoursSeedShare).

**[블록 1] 기간 요약 KPI 밴드** — *"규모와 참여"*
- 가입 학교/교사/학생, DAU·WAU·7일 활성률, 기간 학습활동(periodActs), 누적 학습시간.
- 각 KPI에 "직전 동기간 대비 Δ" 뱃지(가능한 것부터: 주간추이·period-compare 활용).
- 출처: `admin-kpi`.

**[블록 2] 참여·활용 하이라이트** — *"어디에 예산·홍보를 쓸까"*
- 상위 활용 서비스 Top 3(share·재방문율), **저활용/급감 경보 목록**(underused = hard warn/critical만), 관찰 대상(watchList).
- 표본부족(insufficient)은 "판단 보류"로 분리 표기(과경보 금지 계약 준수).
- 출처: `service-ops`.

**[블록 3] 성취·격차 요약** — *"어디에 개입할까" (정책 최상위)*
- 헤드라인 격차: 지역/학교급 avgScore **top vs bottom(격차 pp)**, **CV(변동계수)**, 하위20%비.
- **우선개입 단위 표(priorityUnits = 이중취약 both_low)**: 단위명·학생수·평균성취·활용도 — 성취 낮은 순.
- **학교급×지역 교차(crossLevelRegion)**: 초·중·고 각각의 지역격차 top/bottom 한 줄.
- n<10 마스킹 그대로 존중(개인정보).
- 출처: `equity`(dim=region 및 school_level 각 1회).

**[블록 4] 취약 성취기준 Top N** — *"무엇을 보충할까"*
- 전체(scope=all) 기준 취약·하락 성취기준 랭킹 상위 8~10(코드·교과·지표).
- disclaimer("규칙 기반 신호, 소표본 참고용") 그대로 인용.
- 출처: `weak-trend?scope=all&limit=10`.

**[블록 5] 활동-성취 관계 한 줄** — *"활용 독려가 정당한가"*
- "활동 상위 33% 학생 평균성취 A점 vs 하위 33% B점 = 격차 C pp" 문장 1줄 + 3분위 미니 매트릭스.
- smallSample(n<30) 시 "표본 부족—참고용" 배지.
- 출처: `cross-activity-achievement`(matrix·contentCompare 요약값만).

**[블록 6] 데이터 신뢰도 요약** — *"이 보고서를 믿어도 되나" (반드시 상단 근처 재노출 권장)*
- 성취/교과/시간 **결측률**, **세션 커버리지**, 최근 동기화 시각, xAPI 표본 충분성(≥200?).
- 종합 신뢰도 신호(예: 결측률 최댓값 기준 초록/노랑/빨강 1개 배지) → "지표 해석 시 주의" 여부를 한눈에.
- 출처: `dataset-coverage`(+ `state._xapiSampleCount`).

**[블록 7] 자동 생성 권고 문장** — *규칙 기반 요약 코멘트*
- 위 블록의 임계 초과 항목을 문장으로: 예)
  - "○○지역 초등 성취가 도내 평균 대비 △pp 낮아 보충·연수 우선 검토 대상입니다."
  - "△△서비스 활용이 2% 미만으로 사장 상태 — 홍보 또는 정리 판단이 필요합니다."
  - "성취기준 결측률이 20%를 초과해 성취 지표 해석에 주의가 필요합니다(로거 풍부화 점검)."
- **전부 임계 규칙**(AI 없음). 규칙·임계는 이미 각 API에 존재(status/severity/masked/rate).

**[블록 8/푸터] 근거 데이터 내보내기** — *리포트의 하위 액션*
- 현 `a-export`의 범위(원시/일별/서비스/학급/교과) × 형식(CSV/xlsx) 선택 + 다운로드 이력을 **접이식(details) 섹션**으로 이전.
- 문구: "이 보고서의 근거가 된 원시·집계 데이터를 파일로 내려받습니다."

## 7. 국제 벤치마크 근거

- **국가수준 학업성취도 평가(NAEA) 리포팅 관행**: 성취를 절대 점수가 아니라 **성취수준 구간·지역/학교급 격차** 중심으로 보고. → 관리자 LRS의 핵심을 "평균"이 아니라 **격차(gap·CV)·우선개입 단위**에 두는 것이 정합(현 `equity`가 이미 이 방향).
- **AIDT(AI 디지털교과서) / xAPI·cmi5 학습로그 표준**: 학습활동을 표준 문장(actor-verb-object, 성취기준 노드 매핑)으로 수집·리포팅. → `a-xapi`·`xapi_statement_spool`·`lrs_std_node_stats`가 이 흐름을 대비. 표본 게이트로 "표준 정합 준비도"를 정직하게 노출하는 방식이 적절.
- **KERIS 계열 학습분석·1EdTech(구 IMS) Caliper 거버넌스**: **"성과 분석(analytics)"과 "데이터 품질·표준 정합(data quality/conformance)"을 분리**해 관리한다. → §3 A안(현황 분석 vs 데이터 신뢰성 분리)의 근거.
- **OECD PISA·교육 대시보드 리포트 관행**: 정책 결정자용 산출물은 **원자료가 아니라 "요약 브리프 + 근거 데이터 첨부"** 형태. → §4의 "요약 보고서 본문 + 내보내기는 하위 액션" 구조와 일치. 원시 CSV만 제공하는 현재 '리포트'는 이 관행과 반대.
- **경보 피로(alert fatigue) 회피**: 학습분석 대시보드 실패의 대표 원인은 "빨강 남발". 현 `service-ops`의 MIN_ABS 게이트·seedInfluenced 톤다운·hard/soft/insufficient 3분리는 이 모범을 이미 구현 → 요약 보고서 권고문(블록7)도 동일 임계를 재사용해 일관성 유지.

1. **P0 — 리포트 승격**: `a-export`를 §4 8블록 요약 보고서로 재설계(내보내기는 블록8로 흡수). 백엔드 신규 0, FE 조립 + 인쇄 스타일. **가장 큰 체감 개선.**
2. **P0 — 탭/메뉴 개명**: '운영'→'데이터 신뢰성', '서비스 운영 진단'→'서비스 활용 진단', '내보내기'→'요약 보고서', '표준체계 분석'→'수집 표준 점검'(§6).
3. **P1 — 표본 게이트 통일**: `a-teacher-idx`에 a-xapi식 자동 숨김/빈상태 도입(§5) + 하네스 불변식 박제.
4. **P2(선택)** — `/stats/report-summary` 단일 집계 엔드포인트(캐시·서버 PDF 대비). 필수 아님.
