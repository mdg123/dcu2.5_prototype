## 0. 프리뷰 실측 결과 (설계의 사실 기반 — 반드시 먼저 읽을 것)

`GET /api/lrs/shallow/class/2?days=90` 실측 분포 (2026-07-05):

| 속도 분포 | 빠름 5 · 보통 18 · 느림 0 | ratioMax 1.07 → **"느림" 셀도 현재 데이터로는 0** |
| 노출 콘텐츠 | 2건 ("분수 개념 영상", "소수 곱셈 영상") | 표본≥10 콘텐츠만 노출 |
| maskedContentCount | 123 | 대부분 콘텐츠가 표본<10로 숨겨짐 |

**결정적 사실 두 가지 (설계가 반드시 정직하게 반영):**

1. **현 데이터원(`learning_logs` 중 `target_type='content'` 시청 로그)은 오답을 거의 기록하지 않는다.** 그래서 지금 산점도의 "오답(Y=0)" 라인이 텅 비어 있다. **6셀 매트릭스를 그대로 그리면 하단 3셀(오답×*)이 통째로 빈칸**이 되어, 사용자가 지적한 "회색=무의미/무데이터" 문제가 **더 심해진다.**
2. **정오축을 실제로 채우려면 채점 로그(문항 풀이·평가·오답노트)를 데이터원에 포함**해야 한다. 콘텐츠 문항 풀이(`quiz`/`item`)·평가(`assessment`)·오답노트(`wrongnote`)는 `result_success`에 정답/오답이 모두 찍힌다. → **BE 쿼리 확장이 6셀 매트릭스의 전제조건.**

> 그래서 이 기획서는 (A) BE 데이터원 확장 → (B) 6셀 매트릭스 + 자동 분석 멘트를 **한 세트**로 지시한다. BE 확장 없이 FE만 6셀로 바꾸면 하단이 빈 채로 나가므로 **금지**.

## 2. 6셀(정오 × 속도) 해석 프레임 (사용자 지적 ②③)

### 2-1. 속도 버킷 임계 (데이터 근거)

현 플래그 임계는 `ratio < 0.4`(중앙값의 40% 미만) 단일값. 이를 **3구간**으로 확장한다. 근거: 실측 ratio 분포가 0.22(빠름 클러스터)와 ~1.0(보통 클러스터)로 이봉(bimodal), 중앙값 1.0. 중앙값 대비 대칭·직관 구간으로:

| 버킷 | ratio(= dur / median) 범위 | 의미 |
|------|------|------|
| **빠름(fast)** | `ratio < 0.5` | 반 보통 시간의 절반 미만 |
| **보통(normal)** | `0.5 ≤ ratio ≤ 1.5` | 반 보통 시간과 비슷한 범위(정상) |
| **느림(slow)** | `ratio > 1.5` | 반 보통 시간의 1.5배 초과 |

> 기존 `SHALLOW_RATIO=0.4`(빠름 플래그)는 **더 보수적**이었다. 0.5로 완화하면 "빠름" 셀이 자연스럽게 채워져 6셀 프레임이 성립. `medianThreshold`는 하위호환 위해 응답에 남기되(=0.5로 갱신), 버킷 경계 3값(`SPEED_FAST=0.5`, `SPEED_SLOW=1.5`)을 새 상수로 내려준다.

### 2-2. 6셀 의미 · 색 · 조치 (핵심 표)

색은 **의미 기반**(사용자 지적 ②: "보통=회색"은 금지 → 정상=긍정 초록). 색맹 대비 위해 **색 + 아이콘 + 텍스트 삼중 인코딩**.

| 셀 | 신호(의미) | 색 (배경/글자) | 아이콘 | 교사 조치 1줄 |
|----|-----------|----------------|--------|----------------|
| **정답 × 빠름** | 찍기·요행 가능성 점검(단정 아님) | 주황 `#fffbeb` / `#b45309` | 🟠 | 개념을 실제로 아는지 1문제만 되물어 확인해 보세요. |
| **정답 × 보통** | 정상 학습(가장 바람직) | **초록** `#f0fdf4` / `#15803d` | 🟢 | 잘 하고 있어요. 별도 조치 불필요. |
| **정답 × 느림** | 애써서 맞힘(개념은 맞으나 유창성 부족) | 파랑 `#eff6ff` / `#1d4ed8` | 🔵 | 반복 연습으로 속도를 붙여 주면 좋아요. |
| **오답 × 빠름** | 대충 처리·오개념(가장 주의) | **빨강** `#fef2f2` / `#b91c1c` | 🔴 | 틀린 단원을 오답노트로 다시 확인·보충 배정. |
| **오답 × 보통** | 정직하게 시도했으나 개념 부족 | 빨강(연) `#fef2f2` / `#b91c1c` | 🔴 | 해당 단원 개념 재설명 + 보충. |
| **오답 × 느림** | 오래 고민했지만 못 풂(강한 개념 결손) | 빨강(진) `#fee2e2` / `#991b1b` | 🔴 | 개념을 처음부터 다시. 개별 지도 우선순위. |

**오답 3셀 강화(사용자 지적 ③: "오답은 틀린 이유가 더 중요"):**
- 오답 셀의 드릴/툴팁·표에는 **틀린 단원(성취기준) 라벨**을 함께 표기한다. 데이터는 `achievement_code` → `resolveCode().label`(예: "[6수03-01] 분수의 덧셈").
- **"어느 보기를 골랐나"(선택지 수준)는 로그에 없음** → 정직하게 **개념/단원 수준까지만** 제시하고, 그 이상은 문안으로 안내: `틀린 이유는 오답노트에서 문항별로 확인할 수 있어요.` + `오답노트 보기` / `보충 배정` 연결(가능 시).

### 2-3. 정상=초록의 원칙
- **회색은 "데이터 없음(빈 셀)"에만** 사용. "정상 학습(정답×보통)"은 반드시 **초록**. (사용자 지적 ② 정면 반영)
- 빈 셀은 회색 배경 + 옅은 `해당 기록 없음` 라벨 — "무의미"가 아니라 "이 조합의 학습이 아직 없다"로 읽히도록 문구 명시(§3-3).

## 3. 시각화 재설계 (사용자 지적 ③: 매트릭스로 확장 / 스캔성 우선)

### 3-1. 방식 결정 — **2×3 카운트 매트릭스(주) + 산점도(부·접힘)**

산점도를 유지하되 **주 표현을 2×3 매트릭스로 교체**한다. 이유(교사 스캔성):
- 산점도는 "몇 명이 어느 셀인지" 한눈에 안 들어오고, 오답 라인이 비면 빈 캔버스만 커진다(현 스크린샷의 문제).
- 매트릭스는 **셀별 인원수(카운트)**를 큰 숫자로 보여 줘 "정답×빠름 5명, 오답×느림 2명" 식 즉시 파악. 색으로 위험도 한눈에.
- 산점도는 원하는 교사를 위해 **"자세히 보기(산점도)" 토글로 접어서** 보존(정보 손실 0).

### 3-2. 매트릭스 레이아웃 (데스크탑)

```
                     빠름            보통            느림
         ┌───────────────┬───────────────┬───────────────┐
  정답   │ 🟠 5명         │ 🟢 13명        │ 🔵 0명         │
         │ 찍기 점검      │ 정상           │ 애써 맞춤      │
         ├───────────────┼───────────────┼───────────────┤
  오답   │ 🔴 2명         │ 🔴 1명         │ 🔴 0명         │
         │ 대충·오개념    │ 개념 부족      │ 개념 결손      │
         │ ⤷ 분수 덧셈 외 │ ⤷ 소수 곱셈    │               │
         └───────────────┴───────────────┴───────────────┘
```

- **셀 구성:** (상단) 아이콘 + 큰 카운트 `28px 700`「N명」 → (중단) 셀 이름 `15px 700` → (하단·오답셀만) 틀린 단원 칩 `13px`(최대 2개 + `외 N`).
- **셀 크기·간격:** 그리드 `grid-template-columns: 72px 1fr 1fr 1fr`(첫 열=행 라벨), `gap:10px`. 각 셀 `min-height:104px`, `padding:14px 16px`, `border-radius:12px`, `border:1px solid`(색상 계열 -100). 카운트 0 셀은 `opacity:.55` + 회색 배경 `#f9fafb` + `해당 기록 없음` 대체(§3-3).
- **행/열 라벨:** 왼쪽 세로 `정답`/`오답`(15px 700), 상단 가로 `빠름`/`보통`/`느림`(14px 600 회색). 좌상단 코너에 작은 축 안내 `속도 →` / `↓ 정오`.
- **클릭 드릴:** 각 셀 클릭 → 해당 셀 학생·콘텐츠 목록을 하단 표에 필터링(기존 "속도이상 Top" 표를 **"셀 상세 표"로 승격**, 컬럼: 학생 / 콘텐츠(오답은 단원) / 소요·기준(ratio) / 결과 / 셀 뱃지). `aria-pressed` 토글, 선택 셀 외곽선 강조.
- **색맹 접근성:** 셀은 색 + 이모지(🟢🟠🔵🔴) + 텍스트 라벨 삼중. 표 뱃지도 동일 삼중. `role="grid"`·`aria-label` 부여. 명도 대비 배경↔글자 4.5:1 이상(위 토큰 검증됨).

### 3-3. 빈 셀·빈 상태 (회색=무의미 오해 차단)
- **카운트 0 셀:** 배경 `#f9fafb`, 글자 `#9ca3af`, 문구 `해당 기록 없음`(❌ 회색 점 아님). 툴팁: `이 조합의 학습 기록이 아직 없어요.`
- **전체 빈 상태(points 0):** 기존 긍정 톤 유지하되 문구 갱신 — `최근 '점검이 필요한' 풀이 신호가 없어요. 대부분 정상 속도로 정답을 맞히고 있어요 👍`
- **오답 데이터 0인데 정답만 있는 경우(현 class 2 상태):** 하단 오답 행 전체가 "해당 기록 없음"이 되므로, 매트릭스 상단에 안내 배너 1줄: `이 기간에는 채점된 오답 기록이 없어, 정답 행만 표시했어요.` (BE `hasWrongData=false` 플래그로 제어)

### 3-4. 산점도(부, 접힘) 개선
- `자세히 보기(산점도)` 토글(`<details>` 또는 버튼)로 접음. 펼치면 기존 산점도 렌더하되:
  - **점 색을 6셀 색으로** 매핑(현재 빨강/회색 2색 → 6색). 정답×보통=초록.
  - Y축 라벨 "정답/오답" 유지, 배경에 속도 3구간 세로 밴드(빠름/보통/느림) 옅게 표시 + median 점선 유지.
  - 오답 데이터 없으면 "오답 라인 데이터 없음" 워터마크 표기.

### 3-5. 반응형
- **<768px:** 매트릭스는 `grid-template-columns: 60px 1fr 1fr 1fr` 유지하되 카운트 `24px`, 셀 이름 2줄 허용, 단원 칩 1개+`외 N`. 셀 `min-height:88px`. 산점도 토글은 기본 숨김(모바일은 매트릭스+표만). **가로 스크롤 0** — 매트릭스가 폭을 넘기면 셀 이름을 숨기고 카운트+아이콘만 남긴 뒤 표로 상세 이관.
- **<480px:** 3열 유지가 좁으면 열 라벨(빠름/보통/느림)을 아이콘화(⚡/•/🐢)하고 셀 이름 생략, 상세는 표로.

## 4. 분석 멘트 — 학급 수준 자동 해석 (사용자 지적 ④, **이 카드의 핵심**)

매트릭스 위(또는 바로 아래)에 **규칙 기반 자동 문장 1~2개**를 붙인다. "그래서 뭘 하라는 거지"에 답하는 **관찰 → 해석 → 다음 행동** 3부 구조.

### 4-1. 멘트 규칙표 (우선순위 순 · 최대 2개 노출)

각 규칙은 조건 충족 시 문장을 생성. **위험도 높은 것부터 최대 2개**만 노출(과다 경고 방지). 항상 최소 1개는 나가도록 폴백 포함.

| 우선 | 조건(집계 기준) | 톤/색 | 문안(템플릿) |
|------|----------------|-------|--------------|
| 1 | `오답×느림 ≥ 1명` | 🔴 위험 | 오래 고민하고도 틀린 학생이 {n}명 있어요. 개념 결손이 의심돼요 — 개별 지도를 우선해 주세요. |
| 2 | `오답 총합 ≥ 3명` **또는** 특정 단원 오답 ≥ 2명 | 🔴 주의 | 오답이 특정 단원(**{unit}**)에 몰려 있어요. 그 단원 보충을 배정해 보세요. |
| 3 | `정답×빠름 ≥ max(3, 반인원 20%)` | 🟠 점검 | 정답을 아주 빨리 처리한 학생이 {n}명이에요. 찍었을 가능성이 있어, 개념을 한 번 확인해 보면 좋아요. |
| 4 | `정답×느림 ≥ 3명` | 🔵 참고 | 맞히긴 했지만 시간이 오래 걸린 학생이 {n}명이에요. 반복 연습으로 유창성을 키워 주세요. |
| 5(폴백) | 위 미해당(=대체로 정상) | 🟢 긍정 | 대부분 정상 속도로 정답을 맞히고 있어요. 지금 리듬이 좋아요 👍 |

- `{unit}` = 오답이 가장 많이 몰린 성취기준 라벨(BE가 계산해 내려줌, §6).
- `{n}` = 해당 셀 인원수.
- **단정 금지 톤**([[준수]]): "찍었다"가 아니라 "찍었을 가능성", "확인해 보면 좋아요"(권유). 오답을 학생 탓으로 몰지 않음 — "개념 결손이 의심"(현상 기술) + 교사 행동 제안.

### 4-2. BE vs FE 파생 — **BE 계산으로 지시**
- 멘트 규칙은 **BE(`getShallowLearning`)에서 계산해 `insights[]`로 내려준다.** 이유:
  - (a) 오답 몰린 단원(`{unit}`) 산정은 서버의 `achievement_code` 집계가 필요 — FE에 원자료를 다 내리는 것보다 서버 집계가 정확·경제적.
  - (b) 다른 LRS 카드에도 같은 "분석 멘트" 패턴을 재사용할 것이므로, **서버가 규칙을 소유**해야 일관·테스트 가능(하네스로 회귀 박제).
- FE는 `insights[]`(각 `{level, icon, text}`)를 받아 **렌더만** 한다. FE 하드코딩 문안 금지.

## 5. LRS 전반 "분석 멘트" 공통 컴포넌트 규격 (재사용 패턴 · 사용자 지적 ④ 확장)

이 카드를 본보기로, 성취 매트릭스·교과별 활동·정서-참여 교차·학기말 도달 예상 등 **모든 LRS 카드에 붙일 수 있는 공통 규격**을 정의. (타 카드 실제 적용은 후속.)

### 5-1. 컴포넌트명 `lrs-insight` (분석 멘트 박스)

- **위치:** 카드 헤더(제목·부제) 바로 아래, 차트/매트릭스 **위**. (교사가 그래프를 해석하기 전에 결론을 먼저 읽도록.)
- **구조:** `아이콘 + 문장` 1줄, 최대 2개 스택. 각 문장 = 관찰+해석+행동 한 문장(60~90자).
- **톤/색(레벨별):** 기존 코칭 박스(`#f0f7ff` + `border-left:4px solid #2563eb`)를 확장한 4레벨 좌측 보더 색:
  | level | 좌보더/배경 | 아이콘 |
  |-------|------------|--------|
  | `danger` | `#ef4444` / `#fef2f2` | 🔴 |
  | `warn` | `#f59e0b` / `#fffbeb` | 🟠 |
  | `info` | `#2563eb` / `#eff6ff` | 🔵 |
  | `good` | `#16a34a` / `#f0fdf4` | 🟢 |
- **CSS 스케일:** `padding:14px 18px`, `font-size:16px`, `line-height:1.7`, `border-radius:8px`, 문장 앞 아이콘 `18px`. (본문 16px 준수, 12px 금지)
- **길이:** 한 문장 최대 2줄. 2개 초과 금지(정보 과부하 차단).
- **데이터 계약:** 각 카드 API가 `insights: [{ level:'danger|warn|info|good', icon:'🔴', text:'…' }]`를 내려주고, FE 공통 렌더 함수 `renderInsights(host, insights)`가 그린다. **모든 LRS 카드 공용.**
- **접근성:** `role="note"` + `aria-label="분석 도움말"`. 색만으로 구분하지 않도록 아이콘·텍스트 병기.

> 후속 작업 지시(별도): `renderInsights()` 공통 함수 1개 추가 → shallow 카드에 우선 적용 → 이후 mastery/subject/emotion-engage/forecast 카드 API에 `insights[]` 순차 추가.

## 6. BE / FE 데이터·렌더 지시 (개발자 즉시 구현용)

### 6-1. Backend (`db/lrs-analytics.js getShallowLearning` + `routes/lrs.js`)

**(1) 데이터원 확장 — 정오축을 실제로 채우는 핵심 변경**
- 현재 쿼리는 `target_type/target_id` 있는 모든 로그를 대상으로 하되, 콘텐츠 시청 로그가 대부분이라 오답이 없다. **채점형 활동을 포함**하도록:
  - `result_success`가 0/1로 실측된 로그를 우선(문항 풀이·평가·오답노트). `duration_sec>0` 조건 유지.
  - 그룹핑 키를 `target_type:target_id` 유지하되, **정오 rows를 모두 push**(현재도 push하나 오답 원자료가 없을 뿐 — 데이터원 확장으로 자연 충족).
  - `hasWrongData` = (오답 row ≥ 1) 플래그 계산해 응답에 포함(§3-3 배너 제어).
- **표본<10 마스킹은 유지**하되, 채점형 활동은 콘텐츠 시청보다 표본이 적을 수 있으므로 `SHALLOW_MIN_CONTENT_SAMPLE`를 채점형에 한해 **5**로 완화 검토(문항 세트는 응시 인원=반 인원 수준이면 충분). — 개발자는 실 데이터로 확인 후 5 또는 10 택1, 근거를 커밋 메시지에.

**(2) 속도 버킷 3구간 상수화**
```js
const SPEED_FAST = 0.5;   // ratio < 0.5  → 빠름
const SPEED_SLOW = 1.5;   // ratio > 1.5  → 느림 (그 사이 = 보통)
```
각 point에 `speed: 'fast'|'normal'|'slow'` 필드 추가.

**(3) 6셀 카운트 + 오답 단원 집계 (신규 반환 필드)**
```js
matrix: {
  correct: { fast: N, normal: N, slow: N },
  wrong:   { fast: N, normal: N, slow: N }
},
wrongUnits: [ { code:'[6수03-01]', label:'분수의 덧셈', count: 3 }, ... ],  // 오답 몰린 단원 desc
hasWrongData: true|false,
```
- `matrix`는 point들을 `correct × speed`로 카운트한 6개 값.
- `wrongUnits`는 오답 point를 `achievement_code`로 묶어 count desc(상위 5).

**(4) 자동 분석 멘트 (신규 반환 필드) — §4-1 규칙을 서버에서 평가**
```js
insights: [ { level:'danger', icon:'🔴', text:'오래 고민하고도 틀린 학생이 2명 있어요. …' }, ... ]  // 최대 2개, 최소 1개(폴백)
```
- §4-1 우선순위표대로 조건 평가 → 상위 2개. 항상 폴백(good) 1개 보장.
- `{unit}`는 `wrongUnits[0].label`, `{n}`은 해당 셀 카운트.

**(5) 하위호환·기존 필드 유지**
- `points[]`(speed 필드 추가), `topStudents[]`, `maskedContentCount`, `disclaimer` 유지.
- `medianThreshold`는 `SPEED_FAST(0.5)`로 갱신.

**(6) 하네스(필수 — [[project_test_harness]])**
- `test/regression.test.js`(또는 lrs 전용)에 불변식 추가:
  - `matrix` 6칸 합 == `points.length`(정오·속도 버킷 누락 0).
  - `insights.length` ∈ [1,2]이고 각 `level`이 4종 중 하나.
  - `hasWrongData===false`이면 `matrix.wrong.*` 전부 0.
  - `wrongUnits` count desc 정렬·합 ≤ 오답 총수.
  - 속도 버킷 경계값(ratio=0.5, 1.5) 정확 분류(경계 테스트).
- 수정 후 `npm test` 그린 확인 후 보고.

### 6-2. Frontend (`public/lrs/index.html renderShallowLearning`)

**(1) 헤더** — 제목 `⏱️ 풀이 속도-정확도 점검`, 부제 2줄(§1), 도움말 팝(§1). period/mask 칩 유지. `hasWrongData===false`면 안내 배너 1줄(§3-3).

**(2) 분석 멘트 박스(`lrs-insight`)** — 헤더 바로 아래, 매트릭스 위. `d.insights`를 §5-1 규격으로 렌더(공통 `renderInsights()` 도입 권장).

**(3) 2×3 매트릭스** — §3-2 그리드. 셀 = 아이콘+카운트+이름(+오답 단원 칩). 색 §2-2 토큰. 0셀 §3-3 처리. 클릭 → 하단 상세 표 필터(`aria-pressed`).

**(4) 상세 표(기존 "속도이상 Top" 승격)** — 컬럼: 학생 / 콘텐츠(오답은 단원 라벨) / 소요·기준(ratio) / 결과 / 셀 뱃지(6색). 매트릭스 셀 선택 시 필터. 모바일=카드형(기존 `.shallow-card` 재사용).

**(5) 산점도(부·접힘)** — `자세히 보기(산점도)` 토글. 점 6색 매핑, 속도 3밴드 배경, median 점선 유지. 모바일 기본 숨김.

**(6) 반응형·가로스크롤 0** — §3-5. 스크린샷으로 데스크탑/모바일 실측(빈 셀·겹침·잘림 4종 점검).

**(7) 색 토큰(요약)**
